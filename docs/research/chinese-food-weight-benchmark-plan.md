# 中餐称重 Benchmark 采集方案（v1，2026-10-28）

目标：建立一套可复现、可发表的中餐克重估算评测集，用来（1）对外给出可检验的误差数字，（2）比较不同拍法、参照物和估算方法，（3）同期评测市面 App 与通用多模态模型。

本文是方案；采集通道的代码见本分支 `feat/research-weight-samples`（小程序「称重科研数据」页、后端 `research_weight_samples` 表、后台审核页）。

## 1. 原则

1. **一份菜只称一次真值，多种拍法各拍一组。** 拍摄条件是数据字段，不为每种方法单独采集。以后换方法，只需在同一批数据上重跑。
2. **按超集采集。** 分项真值（能推出总重）、原图、俯拍 + 45°、有/无参照物、短视频。只有新方法需要当时没采的传感器输入（例如深度、标定卡）时才需要补采。
3. **边打边称，不事后拆。** 分项用累加称重：碗放秤上，每加一样读一次数，增量即该项重量。
4. **评测照片里不能出现秤的读数。** 读数单独拍照留证，避免模型"看秤作答"。
5. **数据分级，测试集冻结。** 只有金标进入对外数字；测试集不参与任何调参或提示词修改。

## 2. 数据分级

| 等级 | 来源 | 真值 | 用途 |
|---|---|---|---|
| A 金标 | 自己团队、合作的食堂阿姨（有人在旁录入） | 分项累加称重，完整拍摄 | 冻结测试集，论文与对外数字 |
| B 银标 | 拿到秤的粉丝/共建者，审核通过 | 整份或分项，拍摄齐全 | 扩充家常菜、外卖覆盖；可作公开验证集 |
| C 铜标 | 普通用户上传，审核通过但证据不完整 | 整份 | 开发集、训练，不进对外数字 |

等级由后台审核时判定，不由用户自选。

## 3. 每条样本的字段

| 类别 | 字段 | 说明 |
|---|---|---|
| 场景 | `scene` | canteen 食堂 / home 家里 / takeout 外卖 / restaurant 餐馆 / other |
| | `venue_name`、`city`、`dish_name` | 食堂或餐厅名、城市、菜名（用户口径） |
| 称量 | `weighing_mode` | whole 整份 / itemized 分项累加 |
| | `container_type`、`tare_grams`、`tare_mode` | 容器类型；皮重；measured 称了空容器 / zeroed 秤已去皮 |
| | `gross_reading_grams` | 整份模式：连容器总读数 |
| | `items[]` | 分项模式：每项 `name`、`cumulative_reading_grams`（秤上累计读数）、`contains_bone`、`contains_soup`、`cooking_method`；服务端计算 `grams` |
| | `total_net_grams` | 服务端计算：整份 = 总读数 − 皮重；分项 = 最后读数 − 皮重 |
| | `scale_precision_grams` | 秤的精度（0.1 / 1 / 2 g） |
| 照片 | `photos[]` | 每张带 `role` 与拍摄时间、来源（相机/相册） |
| | 读数证据 | `tare_scale` 空容器或归零读数；`gross_scale` 整份读数；`item_scale` 每加一项的读数 |
| | 评测照片 | `eval_top` 俯拍（必需）、`eval_angle` 约 45°（必需）、`eval_top_ref` / `eval_angle_ref` 加参照物（可选） |
| | `reference_object` | chopsticks / spoon / card / hand / other / none |
| | `video` | 3–5 秒环绕视频（可选，≤8MB） |
| 设备 | `device` | 手机品牌、型号、系统（小程序自动读取） |
| 管理 | `status`、`quality_tier`、`review_note`、`reward_credits`、`benchmark_sample_id` | 审核状态、等级、备注、奖励、入评测集后的样本 ID |
| 授权 | `consent_version`、`consented_at` | 研究用途与公开发表授权版本 |

### 菜型配额（第一版目标约 1000 份整份 + 300 份分项）

主食、混炒、盖浇、汤面汤粉、带汤炖菜、带骨肉、油炸、凉菜、计数型（饺子包子）、多格餐盘/外卖盒。每类至少 60 份整份、20 份分项；不足的类优先补。

## 4. 采集渠道与流程

### 4.1 食堂站点（A 级主力）

- 设备：0.1 g/3 kg 或 1 g/5 kg 电子秤、手机支架、湿巾。秤保持干净，放在阿姨允许的位置。
- 角色：阿姨只负责往秤上的碗里依次打菜；学生/团队成员在旁用小程序「称重科研数据」录入读数并拍照。阿姨不需要操作手机。
- 报酬：按时段给阿姨（建议一个高峰 50 元），不按份计；提前和窗口负责人打招呼。
- 对象：团队和兼职学生自己点的餐（反正要吃），一个窗口一个高峰约 30–50 份分项。
- 整份采集：食堂碗盘规格统一，每种碗先称一次空碗皮重，之后连碗称即可，能采别人的餐（出口站点，给 5 元或会员时长）。

### 4.2 粉丝/共建者（B 级）

1. 先发视频（"AI vs 我自己估 vs 秤"），招募共建者。
2. 门槛：先用自己的秤完成 5 条并审核通过，再寄秤；寄秤后约定完成 30 餐。
3. 奖励：审核通过发积分；储值券/会员时长按条数线下批量发放；共建者名单进入数据集致谢。
4. 质检：读数照片单独拍；后台核对读数照片与填写读数；明显不合理的克重（如一碗面 30 g）标出复核；抽检。

### 4.3 小程序普通用户（C 级）

同一入口开放给所有登录用户，审核通过后按等级入库；不进对外数字。

## 5. 小程序采集流程（已实现）

入口：「贡献食物数据」→「称重科研数据」；也可直接打开 `packageExtra/pages/research-weight/index`（用于视频挂载/二维码）。

1. 首次进入阅读研究授权并勾选同意（版本号随样本保存）。
2. 选场景、称量方式、容器、秤精度，填菜名和地点。
3. 称重：拍空容器（或归零）读数并填皮重 → 整份：拍连容器读数并填数；分项：每加一样填名称和秤上累计读数并拍读数照片。页面实时显示每项增量和净重。
4. 评测照片：把食物从秤上拿下，拍俯拍、45°；可选加参照物再拍一组，可选录 3–5 秒环绕视频。
5. 提交。草稿自动保存在本机，中途退出可继续。
6. 页面底部显示我的提交数量与审核状态。

## 6. 后台审核（已实现）

后台「称重科研数据」页：按状态/方式/场景筛选；详情按角色分组显示照片、填写读数与服务端计算克重；操作：通过（选等级 A/B/C、奖励积分）、驳回（写原因）、加入评测集（写入 `food_weight_labeled_samples`，批次名可填，默认 `research-YYYYMM`），之后可直接在现有 Benchmark 页跑评测。

## 7. 评测与论文

- 指标：总重与分项的 MAPE、MAE、RMSE；Bland-Altman（营养学效度研究惯例）；按菜型、拍法、参照物、设备分层。
- 对照：同一批照片在指定日期用市面 App 与通用多模态模型各估一次，记录版本与日期。
- 关键分析：第二张角度、参照物、视频分别带来多少误差下降——这是可发表的结论，也直接指导用户怎么拍。
- 发表路径：营养/移动健康期刊的效度研究（较稳），或计算机方向数据集赛道（需更大规模）。
- 伦理：涉及招募参与者，投稿前通过合作方所在单位的伦理审查；样本授权单独勾选。
- 利益冲突：论文声明；评测由合作方执行或复核；失败案例写入报告。
