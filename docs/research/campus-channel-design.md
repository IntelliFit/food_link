相关文档：[中餐称重 Benchmark 采集方案](chinese-food-weight-benchmark-plan.md)、[称重科研计划 v2](research-weight-v2-takeout-design.md)、合作提案草稿 [campus-channel-partner-proposal.md](campus-channel-partner-proposal.md)。

## 0. 一页结论

1. **高校通道是"组织 + 活动"级别的采集**：一个社团在一个时间窗口里发起活动，成员扫码加入，提交的数据自动带上学校、社团、活动归属。个人「称重科研计划」不变，高校通道复用它的称重流程，只是多了归属和活动规则。
2. **数据按"克重从哪来"分四层，只有用秤称出来的三层是真值**：自带秤、称重站、同一道菜称多份；没有秤的成员用精准模式拍照，那是模型估算，只用来扩充食堂菜品、看大家吃什么、给社团出报告，**永远不进 benchmark 标签**。
3. **没秤的成员也能出真值**：活动里办"称重日"，社团把秤摆在食堂或训练场，大家端着自己的餐过来称一下。顺带把一部分精准模式记录也称了，用来给估算层标误差。
4. **首批多校同时开**：清华、北大、上交，加你熟悉的几所。清华、北大已有食堂菜品库，可以直接称重；上交几乎没有菜品数据，第一周先用现有「食堂采集」把菜单采上来。
5. **你的 V1.1 合作初稿保留**："社团采菜品 + 做内容，我们给会员和荣誉，首批不给现金"。本方案补上称重和精准模式两块，提案里只加几条，见第 3.4 节。
6. **试点要的代码不多**：活动表、成员加入、样本带归属、活动期间赠送标准版、简单排行榜。社团营养报告第一个月由我们离线出，看板等试点跑通后再做。
7. 需要你拍板的点集中在[第 9 节](#9-待你决定)。

## 3. 合作模式与各方价值

### 3.1 各方得到什么

| 参与方 | 出什么 | 得到什么 |
|---|---|---|
| 健身社团 | 组织成员、办称重日、协助采菜单 | 社团营养报告（成员整体饮食结构、蛋白质来源、各食堂高蛋白/平价选择）；活动素材（"AI vs 我 vs 秤"挑战）；秤（达标后留给社团）；共建证书、优秀团队展示、数据集致谢；校际排行榜 |
| 社团成员 | 称重或拍照记录自己在食堂吃的饭 | 活动期间标准版会员（能用精准模式）；称重样本积分；个人"估重眼力"成绩（自己估 vs 秤）；数据集致谢署名 |
| 食堂（第二步再谈） | 允许在指定位置称重；可选：提供标准份量、标准菜谱 | 菜品营养数据（可做营养标识）；每道菜的份量波动报告；学生最常吃、最想要的菜 |
| 我们 | 工具、审核、会员、秤、报告 | 中餐称重真值（benchmark）；多校食堂菜品库与份量分布；种子用户；"与 X 校社团共建"的品牌 |

### 3.2 首批怎么开

多校一起开没问题，但各校起点不同，按"有没有菜品库"分两类，规程一样：

- **A 类（已有菜品库：清华、北大）**：第 1 周就能称重、拍照，记录可以直接挂到已有的菜上。
- **B 类（菜品库空：上交等）**：第 1 周先由社团里 2–3 个人用「食堂采集」采 1–2 个食堂的菜单，同时开放称重；第 2 周起精准模式记录才能挂到菜上。

每校只要一个社团、一个对接人。多校同时开时，真正的瓶颈是**我们的审核人力**，不是社团，见第 6.3 节。

### 3.3 谁出面、签什么

| 对象 | 谁出面 | 签什么 |
|---|---|---|
| 社团 | 社长或活动负责人（个人身份签） | 你的「合作确认书 V1.1」，补第 3.4 节几条 |
| 成员 | 本人 | 小程序里加入活动时勾选研究授权（v2 已有，版本号随样本保存），不另签纸面文件 |
| 食堂 | 饮食服务中心 / 后勤，或承包商经理 | 第二步再谈；一页合作函即可（见提案草稿的食堂版） |

社团一般不是法人，初稿"实际签约的个人 / 有权签约组织"的写法是对的。不给现金，就不涉及社团收款的问题。

### 3.4 对 V1.1 初稿的补充（详见提案草稿）

1. **合作内容**加"称重与拍照记录"：有秤的成员按小程序规程称重，没秤的用精准模式拍照记录；称重日由社团组织。
2. **科研数据的授权期限**：初稿第 3 条是"2 年内用于产品展示、营养分析及宣传"。称重样本要进公开评测集和论文，这条需要写明：成员在小程序里勾选了研究授权的称重样本，可长期用于研究和公开数据集，不受 2 年限制。
3. **秤的借用**：每校借出若干台，活动结束达标留给社团，不达标收回。
4. **营养结果标注**：初稿已写"AI 营养信息标注估算"。称重样本的克重是实测，可以标"实测"，两者分开写。

## 4. 数据分层（核心）

### 4.1 四层数据

| 层 | 谁、在哪 | 克重怎么来 | 是不是真值 | 存在哪 | 用途 |
|---|---|---|---|---|---|
| **W1 自带秤** | 有秤的成员，食堂打包回去、宿舍、外卖 | 称重科研 v2 流程（多盒、吃完称、常用容器） | 是（B 级，审核后） | `research_weight_samples`，渠道 `campus_self_scale` | benchmark 验证集 / 测试集；份量分布 |
| **W2 称重站** | 称重日，社团在食堂或训练场摆秤，成员端着自己的餐来称 | 统一的秤和托盘，托盘皮重预先存为活动共用容器 | 是（A 级候选：有人在旁、规程统一） | 同上，渠道 `campus_station`，带称重日场次 | benchmark 测试集主力；给精准模式标误差（4.5） |
| **W3 同菜多份** | 同一窗口同一道菜称 5–10 份 | 成员轮流买同一道菜称重（他们反正要吃）；食堂同意后可以让阿姨按标准份打到秤上 | 是 | 同上，渠道 `campus_same_dish`，挂菜品 ID | 每道菜的份量分布；给精准模式记录当弱标签（4.3） |
| **E 精准模式估算** | 没秤的成员，日常在食堂吃饭时拍照 | 模型估算（俯拍 + 45° 两张，精准模式） | **否** | 普通 `user_food_records` + `analysis_tasks`，另用关联表挂活动和菜品 | 见 4.2，**不进 benchmark 标签** |

W1–W3 的流程都是现有称重科研 v2，只多带活动归属和菜品 ID；E 层就是正常记一餐，后台在记录保存后挂一行关联。

### 4.2 精准模式数据为什么不能当标签，能用来做什么

**不能当标签**：拿我们模型的估算当答案，再用它来考我们的模型，模型永远"答对"。哪怕换别家模型来考，测的也只是"像不像我们的模型"，不是"准不准"。用户手动改过的克重同样不是真值（人眼估重误差往往更大），只单独标成 `user_adjusted`。

**也不能拿来训练**：用自己的输出训练自己，只会把现有偏差固化下来。

**能做的事**：

1. **食堂菜品库**：哪些菜被吃得最多、哪些菜库里还没有。没有的菜进「食堂采集」补上，被吃得多的菜优先去做 W3 称重。成员拍的照片可以作为菜品图候选。
2. **校园饮食结构**：三餐时间、主食和肉菜比例、食堂与外卖占比、训练日和休息日的差别。只看相对比较和趋势，并标上 4.5 里测出来的误差范围。
3. **社团营养报告**：同上口径，按社团汇总。
4. **模型稳定性**：同一道菜被多次拍照估算的离散程度，和 W3 实测的份量波动对比。这件事不需要标签。
5. **按菜找系统偏差**：某道菜的精准模式估算分布对比它的 W3 实测分布。比如模型总说宫保鸡丁 300 g，实测是 220 ± 30 g，就能发现偏差。这是用独立真值在**分布层面**做的检验，不循环；但不能据此说某一餐估得准不准。
6. **决定下一次称什么**：模型最没把握、各次估算差得最远的菜型，下一次称重日优先称。

### 4.3 同一道菜的份量分布当弱标签

- 同一窗口、同一道菜称 5–10 份，得到这道菜的份量分布（均值、标准差、P10–P90）。
- 精准模式记录挂到这道菜上之后，"这一份大概率在 P10–P90 之间"就是它的**弱标签**。用法是按菜统计估算落在区间里的比例、整体偏高还是偏低，不当作单条样本的答案。
- 弱标签成立的前提：同一窗口、同一时期（换菜单或换阿姨后重新称）；学生加饭、少饭单独记下（称重时备注）。
- 由成员买来称，反映的是学生**实际拿到**的份量，包括不同阿姨、不同时段的差异，比食堂申报的标准份更贴近真实。食堂提供的标准份量和菜谱另记为"食堂申报"来源，三种来源分开存。

### 4.4 存放规则：真值和估算从结构上分开

- 每条克重都带来源 `label_source`：`scale_measured`（W1/W2/W3）、`canteen_declared`（食堂申报）、`model_estimate`（E）、`user_adjusted`（用户改过的估算）。
- **真值只存在** `research_weight_samples`（以及食堂不让拍照时的轻量称重表，见 7.3）。E 层只在关联表里，**不写进** `research_weight_samples`。
- 进评测集（`food_weight_labeled_samples`）只能走现有的"审核通过 → 加入评测集"路径，这条路径只读 `research_weight_samples`。E 层数据在代码上根本没有入口能进评测集。评测集的 `metadata` 里带上渠道、学校、活动，方便按来源筛选。
- 导出数据集时按 `label_source` 分文件，估算层不会和真值混在同一张表里。

### 4.5 给精准模式标误差：称重日顺带称一部分

- 称重日，没秤的成员照常先用精准模式拍照记一餐，再端到称重站上秤。这一餐同时有一条精准模式记录和一条 W2 称重样本，两者互相关联（`paired_food_record_id`）。
- 攒到每校 50–100 对，就能给出"精准模式在这所学校食堂的实际误差"，报告和社团营养报告里的估算数字都可以带上误差范围。
- 这些配对也是可发表的"真实场景误差"，但评测模型时仍只用称重真值和评测照片重跑，不用当时记下的估算。

## 5. 和个人称重计划的关系：机构、活动、成员

### 5.1 概念

| 概念 | 含义 | 现有可复用的 |
|---|---|---|
| 学校 / 校区 / 食堂 / 窗口 | 已有目录 | `schools`、`school_campuses`、`school_canteens` 和窗口表 |
| **社团（机构）** | 健身社团、校队、学生会等；属于一所学校 | 新表 `campus_orgs` |
| **活动** | 一个社团的一期采集，有起止时间、开放的数据层、目标和奖励规则、加入码 | 新表 `campus_campaigns` |
| **成员** | 扫码加入活动的用户，角色是成员 / 管理员 / 称重日志愿者，记录有没有秤 | 新表 `campus_campaign_members` |
| 菜品 | 食堂菜品库 | `campus_food_catalog_items` |
| 菜单采集 | 社团里指定的人采菜单 | 「食堂采集」+ 采集员申请/授权（`campus_collector_*`），按窗口计奖励 |
| 扫码归因 | 二维码访问、注册转化统计 | `marketing_qr` 的访问、事件和漏斗统计（加入码当作 campaign_code） |
| 活动期会员 | 活动期间赠送标准版 | 会员赠送记录（来源类型/来源键）+ `grant-paid-membership-campaign` 脚本 |
| 积分 | 称重样本审核通过后发分 | 称重 v2 的积分规则和积分流水 |
| 现金 | 首批不用 | 推广员的提现（微信转账、首次提现实名）以后要给个人发钱时可以复用 |

### 5.2 归属规则

- 一个用户同一时间只在**一个进行中**的活动里，规则简单，归属不含糊。
- 成员在活动期间提交称重样本，服务端自动写入 `campaign_id` 和渠道；归属在提交时确定，之后不改。活动结束后提交的样本回到个人渠道。
- 精准模式记录：活动成员在活动期间保存的、挂了食堂菜品的记录，服务端在保存后写一行关联。**不改 `user_food_records` 表**，它是热点表，别的功能也在改。
- 个人通道的样本不受影响，渠道默认 `personal`。

### 5.3 排行榜

- **社团 / 校际榜**：按审核通过的称重样本数排，副榜按新增菜品覆盖数排。人均数作为参考显示，避免大社团通吃。
- **社团内榜**：按通过的称重样本数排，显示昵称。
- 不按热量、体重、蛋白质排，避免鼓励多吃或少吃。

### 5.4 社团管理员看板（试点第一个月先离线出报告）

- 成员数、本周活跃数、每人提交 / 通过条数（用于发奖）、离活动目标还差多少。
- 社团营养报告：成员整体的饮食结构、各食堂高蛋白和平价选择；估算数字带 4.5 的误差范围。
- 导出获奖名单。
- 审核由我们做，社团管理员不能审核自己成员的样本（奖励按通过数发，不能自己审自己）。

## 6. 激励与防作弊

### 6.1 激励（不给现金）

| 层级 | 内容 | 条件 |
|---|---|---|
| 社团 | 秤留给社团 | 达到活动目标（例：通过 150 条称重样本） |
| 社团 | 社团营养报告、共建证书、优秀团队展示、数据集致谢 | 完成活动 |
| 社团 | 校际榜前三的物资奖励（运动补剂、器材、活动物资） | 【待决定 D3】 |
| 成员 | 活动期间标准版会员（能用精准模式） | 加入活动即开，活动结束到期【待决定 D1】 |
| 成员 | 称重样本积分（沿用 v2：整份 2、分项 4、多盒 2 + 每多一盒 1，封顶 6） | 审核通过 |
| 成员 | 会员延长（例：通过 ≥ 30 条，延长一个月） | 活动结束结算 |
| 成员 | 采菜单按窗口奖励（现有规则） | 采集员 |

精准模式记录**不按条发奖励**，否则会刷记录；只按"活动期间有记录的天数"计一项参与度，设上限。

### 6.2 防作弊

- 沿用 v2 的检查：皮重 ≥ 连盒读数拒绝、单盒超 5000 g 拒绝、读数照片不能重复使用、"吃完再称"的空盒照片早于评测照片时标红。
- 新增：
  - 同一活动内，读数照片的内容哈希跨用户查重（同一张秤照片不能两个人用）；
  - 每人每天计奖励的称重样本设上限（例：10 条），超出照收但不计分；
  - 克重和这道菜的 W3 份量分布差太远（例：超出 3 个标准差）时标出来复核；
  - 审核通过的样本随机抽 10% 二次复核，复核不过的整批回查该成员；
  - 社团奖励只按"审核通过"计，不按"已提交"。
- 称重日：志愿者只管秤、不替别人提交；每个人用自己的手机提交自己的餐，归属不会乱。

### 6.3 审核成本

- v2 一条样本人工审核约 1 分钟（看读数照片、核对填写、看评测照片）。按 4 所学校、每校一个月 150–300 条算，600–1200 条，约 10–20 小时。
- 多校同时开，审核会先成为瓶颈。**建议把"读数自动识别"（v2 文档里的第二期）提前**：拍秤照片后由视觉模型读数，和填写值一致的直接预审通过，人工只看不一致和标红的。这样能把人工量压到三成左右（估计值，实测后修正）。【待决定 D5】

## 7. 小程序与后台形态

### 7.1 小程序

- **入口**：「我的 → 科研共建」现在只有「称重科研计划」，加第二项「高校共建」；称重科研计划首页如果检测到用户在进行中的活动里，顶部显示"我的社团活动"卡片。
- **活动落地页**（`packageExtra/pages/campus-campaign/index?code=…`）：**游客能看**活动介绍、学校和社团、排行榜；点"加入"才要求登录（符合微信审核要求）。二维码、链接都直接指向这里。
- **成员流程**：扫码 → 看活动 → 登录并加入（勾研究授权，选"我有秤 / 没秤"）→ 活动首页：
  - 进度：社团离目标还差多少、我的提交 / 通过；
  - 「用秤记一顿」→ 现有 v2 记录页，带活动上下文，地点默认本校食堂，可以选窗口和菜品；
  - 「拍照记一顿（精准）」→ 现有分析页的精准模式，先选食堂、窗口、菜品（菜库里没有就填菜名，进待采集清单）；
  - 称重日安排（时间、地点）；
  - 排行榜。
- **管理员**：同一页多一个"管理"标签：成员列表、加入二维码、进度、导出获奖名单。第一个月可以先不做，由我们出报告。
- **称重日**：活动可以有"共用容器"（食堂托盘、碗的皮重预先称好），成员在称重站选它，不用再称空盘。

### 7.2 后台

- 社团和活动管理：建社团、建活动（时间、开放的数据层、目标、奖励规则、会员赠送）、生成加入码和二维码。
- 称重科研审核页：加"学校 / 社团 / 活动 / 渠道"筛选，显示该菜品的 W3 份量分布，方便判断克重是否合理。
- 菜品份量分布页：按菜品看所有 W3 样本，算均值、标准差和区间。
- 活动报告：一键导出社团营养报告的数据（第一个月我们手工整理）。
- 导出：按 `label_source` 分文件。

## 8. 落地节奏

### 8.1 阶段

| 阶段 | 时间 | 内容 |
|---|---|---|
| 准备 | 1–2 周 | v2 上线；M1 + 最小代码（活动、加入、归属、会员赠送、排行榜、精准模式选菜品）；和各校社团谈，改好确认书；每校准备 5–10 台秤 |
| 试点 | 4 周 | 多校同时开。第 1 周：启动分享 + "AI vs 我 vs 秤"挑战 + 第一次称重日（B 类学校同时采菜单）；第 2–4 周：每周 1–2 次称重日，自带秤的成员日常称，W3 每校挑 10 道热门菜各称 5–10 份 |
| 复盘 | 第 5 周 | 看第一个月指标，决定扩校、加看板、提前做读数识别 |
| 扩校 | 第 2–3 个月 | 加学校（优先已有菜品库的：苏州大学 315 道 / 8 个食堂、上海几所、厦门海洋职院等）；社团自助建活动；谈食堂合作 |

### 8.2 第一个月的目标（可衡量）

| 指标 | 每校目标 | 合计（按 4 校） |
|---|---|---|
| 加入成员 | ≥ 20 | ≥ 80 |
| 活跃 ≥ 2 周的成员 | ≥ 10 | ≥ 40 |
| 审核通过的称重样本（W1+W2+W3） | ≥ 150 | ≥ 600 |
| 其中称重日样本（W2） | ≥ 50 | ≥ 200 |
| 做了份量分布的菜（≥ 5 份） | ≥ 10 道 | ≥ 40 道 |
| 挂了菜品的精准模式记录 | ≥ 300 | ≥ 1200 |
| 精准模式 + 称重配对（4.5） | ≥ 25 | ≥ 100，得出第一个"真实场景误差" |
| B 类学校新采菜品 | ≥ 100 道 | — |
| 流程数据 | 实测：自带秤每餐耗时（目标 ≤ 3 分钟）、称重站每人耗时（目标 ≤ 1 分钟）、驳回率（目标 < 15%）、审核周转（目标 ≤ 48 小时） | |

参照：benchmark 第一版目标是约 1000 份整份 + 300 份分项。高校通道第一个月如果能拿到 600 条通过样本，就超过一半。

**止损线**：第一个月合计通过的称重样本 < 200，或驳回率 > 30%，就先停扩校，回头改流程（多半是称重太麻烦或规程没讲清）。
