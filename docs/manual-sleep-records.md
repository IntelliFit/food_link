# 手动睡眠记录

- 首页“整理首页”中的“睡眠”可排序、显示或隐藏。隐藏模块不删除数据。
- 每个账号按起床日期保存一条主要睡眠记录，可补记、修改、删除。按北京时间归档，与现有每日记录保持一致。
- 入睡日期可选前一天或起床当天；记录近似入睡时间、起床时间，质量（好/一般/差）和最多 500 字补充说明均选填。
- 展示的时长只是两次手动填写时间的间隔，包含夜间清醒时间，不是设备测量的净睡眠时间。此次不接手表、不自动改常用作息、不生成健康评分。
- 数据保存到服务端，首页在日期切换、回到页面或保存/删除事件后重新读取。没有新增持久化本地睡眠缓存。

## API

已认证用户访问 `GET/PUT/DELETE /api/sleep-records/:date`，日期格式 `YYYY-MM-DD`。GET 无记录返回 `data: null`。

PUT body 示例：

```json
{"bedtime":"2026-09-27T23:30:00+08:00","wake_time":"2026-09-28T07:00:00+08:00","quality":"fair","note":"半夜醒了两次"}
```

时间间隔须为 1 分钟至 24 小时；起床日期必须与路径一致，不能记录未来起床时间。按用户和日期原子 upsert，重复保存不会新增第二条。同一日期的其他账号记录互不影响。

## 迁移和发布

模型：`backend/internal/migration/do/schema_do.go` 的 `SleepRecordDO`；表 `user_sleep_records`。唯一索引、睡眠区间/起床日期/质量约束与账号删除级联均在迁移代码中定义。

在确认配置指向的目标数据库后，从 `backend/` 执行：

```sh
go run ./cmd/migration -config-dir . -only-sleep-records
```

此命令只新增本功能的表与约束，可重复运行；HTTP 服务不会自动迁移。非本地库执行前须按项目规则获得用户确认，先迁移，再部署后端，最后上传包含睡眠页的小程序版本。
