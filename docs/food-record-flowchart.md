# 食物记录主链路流程图

这张图描述用户记录一餐时的主要路径、后端算法流程，以及需要 benchmark、优化或数据治理的关键环节。

标记说明：

- `[B]` 需要 benchmark
- `[O]` 需要优化
- `[D]` 需要数据治理

```mermaid
flowchart TD
  A["用户想记录食物"] --> B{"入口选择"}

  B --> C1["拍照/相册识别"]
  B --> C2["文字描述记录"]
  B --> C3["手动搜索/自定义食物"]
  B --> C4["历史记录快速复用"]

  D1 --> D2["创建 analysis_task"]
  D2 --> D3["Worker 异步处理"]

  C2 --> D2

  D3 --> E1["视觉模型识别食物清单"]
  E1 --> E2["识别名称、包装线索、OCR、估重"]

  H2 -->|exact/alias/fuzzy/semantic| H3["按标准库每100g营养 + 估重回算"]
  H2 -->|标准库也未命中| I1["DeepSeek/LLM 营养兜底"]

  N --> M

  M --> O1["写入 user_food_records.items"]
  O1 --> O2["保存包装证据、AI比例、营养来源"]
  O2 --> O3["首页/历史/分享图读取记录"]
  O3 --> P["用户看到本餐热量和 PFC"]

  F1 -. "[B/O] 包装食品触发判断" .-> X1["避免普通餐饮误进包装库"]
  G1 -. "[B/O] 包装 SKU 召回 benchmark" .-> X2["防错 SKU、错规格、弱 fuzzy 误命中"]
```

## 这次 0 卡问题的位置

饭饭这次不是分享页算错，而是 `user_food_records.items` 已经保存了错数据：

- `如实酸奶`：普通库和包装库都没命中，最后以 `unresolved + 0营养` 保存。
- `双汇玉米热狗肠`：包装库有正确 SKU，但当时停在 `candidates_only`，没有把候选营养应用进去，也没有兜底。

## 最需要 Benchmark 的点

1. 包装库召回 benchmark：防错 SKU、错规格、弱 fuzzy、品牌/口味误命中。
2. 标准营养库召回 benchmark：防品牌酸奶、口语名、单位短语 unresolved。
3. 保存前 0 营养门禁：非真实零卡食品不能保存成 0。
4. 结果页到保存链路回归：防结果页有营养、保存后字段丢失。
5. 真实任务审计：定期扫描 `analysis_tasks` / `user_food_records` 中非零卡食品的 0 营养记录。

核心原则：候选不能当命中，包装库未命中不能直接结束；应继续标准营养库，再 DeepSeek/LLM 兜底。未命中不能静默保存 0，品牌化普通食物必须能安全退回通用营养库。
