# 视频食物分析算法设计

更新日期：2026-07-30

## 1. 目标与输出边界

视频分析不是把 MP4 直接交给视觉大模型后让模型“目测克重”，而是把任务拆成四个可独立评估的子问题：

1. 食物实例识别：视频中有哪些食物、各有多少个、是否为同一实例。
2. 物理份量估计：每个实例的可见体积、绝对尺度和重量区间。
3. 可食部换算：区分包装、果皮、果核、骨、壳与实际可食重量。
4. 营养映射：使用现有 DB First 营养链路按可食重量计算热量和营养素。

输出必须同时包含：

- `identity_confidence`：食物身份置信度。
- `geometry_confidence`：尺寸、体积和遮挡置信度。
- `density_confidence`：体积换算重量的密度置信度。
- `edible_portion_confidence`：可食部比例依据。
- `weight_range_g`：重量区间，不输出没有证据支持的个位数克重。
- `needs_confirmation`：身份、数量、包装净含量或可食部证据不足时要求用户确认。

## 2. 建议采集协议

- 时长按场景动态控制：单盘约 3–6 秒；聚餐扫桌约 8–20 秒或直到覆盖检测完成。
- 分辨率：至少 1080p，优先 30/60fps。
- 路径：从俯视开始，缓慢移动到约 45°，覆盖至少 60° 水平视角变化。
- 聚餐扫桌：缓慢连续移动，相邻视野保留约 30%–50% 重叠，使同一菜品能够跨段跟踪和去重。
- 距离：食物主体占画面 50%–85%，避免频繁远近拉动。
- 光照：避免强反光、逆光和快速扫动。
- RGB 首版需要绝对尺度来源：已知尺寸餐盘、标定卡、包装尺寸、AR 公制位姿之一。
- 深度版同步采集 RGB、深度图、相机内参、RGB/深度外参、IMU、设备位姿、时间戳和深度置信度。

## 3. 算法流水线

### 3.1 视频接入与标准化

1. 上传原始 MP4 到 COS，分析任务只保存对象 key。
2. 读取时长、旋转、分辨率、帧率、编码和音轨信息。
3. 统一方向与色彩空间，生成低码率预览和无损关键帧。
4. 原视频设置短生命周期；向外部模型传递时使用短时签名 URL。

### 3.2 质量门禁与关键帧

以 5–10fps 解码候选帧，计算：

- 清晰度：Laplacian variance 或学习型模糊评分。
- 曝光：过曝/欠曝像素比例。
- 主体完整度：食物实例是否被裁切。
- 视角新颖度：光流、特征匹配和相机位姿变化。
- 遮挡与反光：包装盒、手、餐具、泡沫网造成的覆盖比例。

不能从整段视频只选固定 3 张“全局最佳帧”。单盘视频中 3 张通常可以覆盖主体，但聚餐扫桌、长桌、多餐盘和镜头平移场景中，不同食物可能从未同时出现在同一帧。

关键帧策略改为覆盖驱动的动态选择：

1. 根据相邻帧特征重叠、相机运动和场景 embedding，把视频切成若干连续视野段 `view_segment`。
2. 在候选帧中检测食物区域或显著物体，建立“帧—可见实例/区域”覆盖矩阵。
3. 使用带质量权重的 set cover / maximum coverage 选择帧：每加入一帧都应覆盖尚未覆盖的新食物或新桌面区域，而不是只追求单帧清晰度最高。
4. 关键帧数量动态变化。单盘可能 3 张；多人聚餐可能需要 6、9、12 张甚至更多。
5. 当前 VLM 单次最多 3 张图时，把关键帧按相邻视野和实例重叠分组，每组最多 3 张、多次调用，最后进行全局去重和融合。“3张”只是一次调用的批大小，不是整个视频的帧上限。
6. 同时保留足够的中间重叠帧供跨段跟踪、相机位姿和三维重建，不能只保存送给 VLM 的语义帧。

原生视频 VLM 作为全局语义复核或 shadow 分支 A/B，不作为唯一结果来源。

#### 场景模式识别

视频进入分析后先区分：

- `single_plate`：单盘或主体始终基本完整入镜，可使用少量多视角帧。
- `table_scan`：镜头横向/环绕扫过多个互不同时入镜的菜品，使用动态覆盖和分组分析。
- `buffet_scan`：长桌/自助餐连续扫描，按空间段生成食物清单。
- `before_after`：同一桌面进食前后扫描，用于估算剩余量变化。

聚餐 `table_scan` 的输出默认是“桌面食物库存和总营养估算”，不能直接等价为某个用户的实际摄入。实际摄入仍需用户选择吃过的菜和大致份量，或由后续持续佩戴硬件跟踪取食事件。

#### 自主帧角色发现与全局关系构建

关键帧不只有“不同视角”，还应区分信息职责，但这些职责必须由算法从任意拍摄顺序中自主发现，不能依赖固定拍摄协议：

- `detail_frame`：贴近某一项或一组食物，提供品种、表面形态、标签、条码、数量边界和局部尺寸证据。
- `overview_frame`：较远距离覆盖多个已扫描食物，提供全局数量、相对位置和跨段去重锚点。
- `bridge_frame`：近景滑向下一项或从近景退到全景的连续过渡帧，负责建立 tracklet 和画面对应关系。
- `transition_frame`：快速移动、严重模糊或主体被裁切，通常不送给 VLM，但可保留低权重运动信息。

样例视频属于“多个近景细节段 → 最后一秒全局概览”。这只是众多有效输入模式之一，不构成产品协议。对于该样例可以：

1. 每个近景段分别选择清晰的 `detail_frame`。
2. 最后的 `overview_frame` 建立画面中的全局食物清单。
3. 使用中间 `bridge_frame`、外观 embedding 和空间位置，把各近景识别结果挂接到全局清单。
4. 全局帧负责防止重复计数，近景帧负责补充全局帧看不清的身份和包装信息。

算法不能假定全景一定出现在最后，不能假定视频中一定存在全景，也不能假定近景、桥接帧和全景的出现顺序。应根据主体覆盖面积、可见实例数量、平均实例尺度、画面重叠和相机运动自主赋予帧角色。若整段没有单张全景，则使用多个相互重叠的局部视野形成全局关系图；区域之间也没有重叠时，必须标记扫描可能不完整。

“起始概览 → 逐项近景 → 结束概览”只能作为可选拍摄引导，用于降低算法难度，不能成为分析成功的前置条件。

#### 通用关键帧发现

任意视频的关键帧选择采用粗到细的迭代过程，而不是一次性取固定 Top-K：

1. **稠密低成本扫描**：以自适应帧率解码低分辨率候选，计算清晰度、运动、场景 embedding、显著物体区域、文字可读性和画面重叠。
2. **时空候选图**：帧或局部区域作为节点，时间连续、外观相似、特征重叠和相机几何作为边，形成可能的实例 tracklet 与场景关系。
3. **第一轮发现**：选择能最大化新食物区域、新场景区域和跨段连接性的少量帧，交给轻量检测器或 VLM 形成初步食物清单。
4. **不确定性驱动补帧**：对身份、数量、OCR、尺度或遮挡仍不确定的项目，回到原视频中寻找更清晰、更大或视角差异更高的候选帧。
5. **边际收益停止**：当新增帧对食物覆盖、身份置信度或几何约束的提升低于阈值，或达到成本预算时停止。

不同下游任务允许选择不同帧集合：

- 语义识别帧：强调食物身份和加工状态。
- OCR 帧：强调包装文字清晰度和正视角。
- 数量/去重帧：强调实例同时可见或跨段连接。
- 几何帧：强调视差、纹理、清晰度和相机基线。

不存在一组对所有任务都最优的“通用关键帧”。

### 3.3 跨帧实例分割与跟踪

1. 首帧检测食物、容器和包装。
2. 使用视频分割/跟踪模型为每项食物生成跨帧稳定的 `track_id`。
3. 将包装盒、泡沫网、标签、蕉皮等建立为独立掩码，防止其体积计入可食重量。
4. 对每个 `track_id` 聚合不同视角，避免同一根香蕉在多帧中被重复计数。
5. 对镜头已经移出后又重新进入的实例，使用外观 embedding、容器形状、相邻轨迹和相机空间位置进行 tracklet 重识别。
6. 若非重叠视野无法可靠判断是否为同一菜品，保留 `possible_duplicate_group`，不得静默合并。

### 3.4 食物身份识别

VLM 输入为：

- 当前 VLM 分组对应的 1–3 张语义关键帧。
- 每项食物的局部裁剪和跨帧实例编号。
- OCR 可读标签、条码和包装净含量。
- 用户补充的餐食/采购场景。

VLM 只输出食物身份、烹饪/加工状态、包装文字和视觉证据，不直接决定最终营养值。多帧结果冲突时按可见度加权投票，不能用单帧高置信输出覆盖其他帧的明确反证。

### 3.5 体积与重量

按传感能力分三级：

#### A. RGB + 参考尺度

- 从关键帧恢复相机位姿。
- 以餐盘、标定卡或已确认包装尺寸恢复绝对尺度。
- 对规则形状使用食物形状先验；对不规则食物使用多视角深度/点云。
- 以桌面或容器底面封闭不可见底部，计算体积区间。

#### B. RGB + 公制设备位姿

- 使用 ARKit/ARCore 或硬件视觉惯性里程计提供公制位姿。
- 多视角立体匹配恢复表面深度。
- 公制位姿解决单目重建的尺度不确定性，但仍需处理反光、透明容器和遮挡。

#### C. RGB-D/ToF/LiDAR + IMU

- 将 RGB 实例掩码投影到深度帧。
- 过滤低置信深度和透明/反光区域。
- 通过 TSDF/点云融合重建每项食物表面。
- 使用 IMU 和同步位姿补偿项链/手持设备的快速运动。

重量计算为：

`重量 = 体积 × 对应食物及形态的密度`

密度应保存为分布或区间，而不是单个常数。混合菜、汤、蓬松食物和被包装遮挡的水果应扩大区间或请求确认。若追求接近称重级精度，摄像设备应与智能餐盘/负载传感器融合。

### 3.6 可食部与营养

需要分别维护：

- 采购/陈列总重量。
- 包装重量。
- 食物毛重。
- 可食部重量。
- 实际摄入重量。

蕉皮、桃核、包装和泡沫网不能进入营养计算。最终营养继续使用现有规则：

`营养总量 = 可食重量 × 每 100g 营养值 / 100`

食物名称进入现有可信营养库精确命中、候选召回和严格身份门禁；未命中时才使用隔离的 AI 营养估算。

## 4. 样例视频初步分析

样例：`77886a0a9a2a791d408948549dde7287_raw.mp4`

视频属性：

- 时长约 5.87 秒。
- 1920×1080，约 60fps。
- 文件约 23.6MB。
- 具有俯视和斜侧视角，适合关键帧识别。
- 存在运动模糊、透明塑料反光、泡沫网遮挡和包装标签不清晰。
- 没有可直接读取的公制相机位姿、深度帧或可靠尺寸参照。

可见食物：

| 食物 | 视觉结论 | 估计可食重量 | 主要不确定性 |
|---|---|---:|---|
| 香蕉 | 5 根，1 根普通偏大、4 根较小 | 400–500g | 蕉皮比例、大小尺度 |
| 蓝莓 | 1 盒 | 125–200g | 标签净含量在视频中不可可靠读取 |
| 黄桃/油桃类 | 约 5 个，泡沫网包装 | 650–850g | 具体品种、数量边界、果核与泡沫网遮挡 |

按普通生鲜食物的通用每 100g 营养值估算整段视频中全部可食部分：

| 指标 | 估计范围 |
|---|---:|
| 热量 | 约 680–890 kcal |
| 碳水化合物 | 约 171–224g |
| 蛋白质 | 约 11–15g |
| 脂肪 | 约 3–4.5g |
| 膳食纤维 | 约 23–31g |

这不是一次称重级结果。区间主要来自蓝莓包装净含量、桃/油桃身份和数量边界、绝对尺度及可食部比例，而不是营养库本身。

## 5. 第一阶段离线 POC

### 5.1 已确认的最简产品版本

第一版不要求用户提供称重真值，采用“视频自动抽取多图，最终交给 VLM 估算”的路径：

1. 用户按场景拍摄：单盘约 3–6 秒；聚餐扫桌约 8–20 秒，由覆盖检测提示何时可以结束。
2. 先识别 `single_plate` 或 `table_scan` 等场景模式。
3. 按未覆盖食物/桌面区域动态选择关键帧，不设置整段视频固定 3 张上限。
4. 自动识别 `detail_frame/overview_frame/bridge_frame`，近景负责身份细节，全景负责库存和去重。
5. 每 1–3 张相关视野组成一个 VLM 分组；多组并行或受控并发分析。
6. 聚合器先以全景建立全局清单，再结合时间相邻性、画面重叠、外观和空间位置，把近景结果挂接到对应全局实例并去重。
7. 结果同时返回中心估计、上下界、估算依据和置信度；证据不足时扩大区间或让用户确认身份/数量，不要求用户先称重。
8. 保存原视频、关键帧选择和结构化模型输出，为以后接入深度/体积算法和离线回放保留数据。

重量估计不只依赖一句通用提示词，应先按食物形态选择方法：

- 可数完整食物：`数量 × 同尺寸等级单体可食重量分布`。
- 有标签包装：优先 OCR 净含量，失败后使用包装外形和同类规格先验。
- 餐盘堆叠食物：根据餐盘占比、堆叠高度和标准份量先验估算。
- 液体：优先识别容器规格和液面比例。
- 混合菜：估算总重量和各成分比例，并扩大油、酱汁和隐藏配料的不确定区间。

VLM 结构化输出应记录 `estimate_method`，例如 `count_prior`、`package_ocr`、`container_geometry`、`visual_portion` 或未来的 `reconstructed_volume`。

### 5.2 精度验证

用户本人不需要为每次使用准备食物秤，但产品团队仍需真值才能回答“算法是否更准”。初期可先使用 Nutrition5k 等带视频、深度、分项重量和营养标签的公开数据做回放；随后建立约 100 份符合中式餐食和本项目拍摄协议的内部称重集：

1. 每项食物分别记录毛重、可食重量和包装净含量。
2. 同时拍摄当前单图和 3–6 秒视频。
3. 对比五组：
   - 当前最佳单图。
   - 自动选择的 3 张关键帧。
   - 原生视频 VLM。
   - 关键帧 VLM + RGB 多视角几何。
   - RGB-D/ToF 融合。
4. 指标：
   - 食物身份 exact/F1。
   - 数量准确率。
   - 重量 MAE、Median APE 和覆盖率。
   - 热量/宏量营养 MAE。
   - 拒识率与用户确认率。
   - P50/P95 时延、模型成本和上传流量。

POC 的成功标准不是“所有结果都有一个数字”，而是在给定误差门槛时覆盖率明显高于单图，并且低置信样本能可靠拒识或请求确认。

## 6. 深度学习体积估计的推荐演进

存在可用的深度学习方法，但不能把“预测出一张深度图”直接等同于“得到了可靠体积”：

1. **单目深度**：Depth Anything V2 等模型可从单张 RGB 图预测相对深度，并提供室内公制深度版本。适合作为食物表面形状先验，但透明盒、反光、泡沫网和训练域差异会造成误差。
2. **多视角重建**：DUSt3R 一类模型可从多张无标定图像预测点图、相机相对位姿和稠密几何，比逐帧单目深度更适合环绕视频。
3. **视频时序深度**：对关键帧深度增加跨帧一致性约束，减少单帧深度闪烁；与实例分割结合后只重建食物区域。
4. **隐式表面/网格**：NeuS、NeuS2、NeRF 或 3D Gaussian 类方法可融合多视角生成表面，再封闭底部并积分体积。它们需要足够视角覆盖，并容易受食物移动、镜面包装和弱纹理影响。
5. **食物专用模型**：VolETA 使用关键帧、分割、相机位姿、参考物、RGB-D 和网格重建完成食物体积估计，证明该路线可行，但其精度依赖参考尺度和深度证据。

第二阶段建议采用：

`SAM2/XMem 跨帧实例 → DUSt3R 多视角点图/位姿 → Depth Anything V2 深度先验 → 已知尺度或公制深度对齐 → 食物网格 → 体积 × 密度分布`

单目或多视角 RGB 仍可能只有“相对大小”。绝对体积必须至少有一种尺度锚点：已知尺寸餐盘/卡片、包装尺寸、AR 公制位姿、ToF/LiDAR 深度或硬件距离传感器。
