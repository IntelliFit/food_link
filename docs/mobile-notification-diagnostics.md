# APP 通知自检与诊断

入口：APP「我的」→「通知自检与诊断」，或「消息提醒」→「手机通知状态」中的诊断入口。Android 原生独立安装包可用，无需开启新的云服务或数据库迁移。

## 自检

点「10 秒后发一条本地通知」只安排一条通用本地通知，沿用 `foodlink-reminders` 业务通道。不调用推送服务，不获取新 token，不保存业务提醒偏好，不申请或绕过系统权限。可以锁屏观察，再记录「看到了 / 没看到」。本地成功不代表远程 FCM 连通。

10 秒是安排时间，不保证系统精确按时触发。沿用 Expo 的现有调度，未获精确闹钟能力时使用非精确调度，不新增精确闹钟权限。页面展示此能力及仍待触发的本账号自检条数；待触发/延后不能当成本地显示失败。

## 证据边界

- `fcm_received`：原生 Firebase 接收器进入，后台 JS 休眠时也能记录。
- `expo_forwarded`：原有 Expo 委托处理函数返回，仅表示已交给 Expo，不等于展示。
- `foreground_received / foreground_allowed / foreground_suppressed`：前台观察与展示决策。
- `opened / local_opened`：用户点击通知。
- 系统已发布数量：Android 当前保留在系统中的本 APP 业务通道通知，不等于本人看到了；已清除的消息不再计入。
- Google 服务启用状态、系统互联网验证、当前网络/省电/休眠是此刻状态，不证明 FCM 接收常连可达或历史测试时的状态。
- 无记录不能证明没有收到：FCM 通知型消息在后台可能自动展示并绕过服务回调；旧消息/安装诊断包前/清除后的事件无法追溯。

## 隐私与兼容

注册也分三段记录：手机原生凭据获取、Expo 凭据注册、业务账号设备绑定。仍复用现有接口，凭据只在内存传递；两个凭据阶段共享原有 20 秒总预算，不新增自动重试或远程测试。失败仅记录有限枚举错误码，原生与导出均使用白名单；不记录 SDK 完整错误、请求体或任何 token。`ready` 仅表示相应注册步骤完成，不代表 FCM 接收连接可达。原生获取失败后 SDK 可能保留失败的请求状态，重新打开 APP 可重新尝试，但不能保证网络问题已修复。

源码预留的 4.6.10（66）是分阶段定位的私有诊断增量，目前尚未构建或交付；本人最新导出仍为 4.6.10（65）。它不是正式版发布或实机推送已修复声明。维持旧安装签名兼容仅用于这次私有诊断，正式发布仍须处理独立正式证书与现有安装/微信签名兼容问题。反诈来电反馈按本人要求暂缓调查，不据此宣称安全通过或误报；不通过换包名/签名来绕过检测。

本机最多 50 条事件，读取时仅展示最近 7 天。只存枚举阶段、时间、前后台状态及通知标识的截断 SHA-256，不存正文、健康数据、token、密码、IMEI 或原始用户 ID。原生日志不输出通知内容。账号只保存不可逆摘要用于匹配；退出/切换会清除事件并取消旧账号尚未触发的本地自检。用户缓存清理和页面清理均可清除事件。

不自动上传；仅诊断 SharedPreferences 文件排除 Android 云备份与设备迁移，其它已有数据的备份策略不变。复制时使用字段白名单，由用户决定将诊断文本交给谁。诊断失败不阻断原有 Expo 接收逻辑；Firebase service 继承现有 Expo service，保留原有 token 与消息委托。合并清单只有一个 APP/Expo 业务接收器，原 Expo service 被替换；Firebase SDK 自带的低优先级回退 service 保留，不是第二个业务接收器。没有新增后端 API、表或迁移。

诊断安装包只是定位工具，不宣称已修复荣耀实机远程送达。原有仅两条远程测试授权仍已用尽，不因安装诊断包自动续发或重发。

Windows 深目录本地构建可设置 `FOODLINK_ANDROID_CXX_BUILD_DIR` 为当前任务独有的短原生输出目录；同时启用 CMake 对象路径摘要。未设置时保持原编译目录，不能复用或清理其它任务的原生输出目录。
