# 宠物成长与游戏 · 第一阶段实施记录

2026-10-02。对应本目录 `report.md` 的分阶段路线，落实单机成长与收集主线。本文记录代码实际实现与验收边界，不把候选渲染图、单元测试或开发数据当成真实账号完整验收。

## 1. 用户入口与玩法闭环

现有宠物聊天中的「伙伴时光」入口保留；宠物档案页也可进入。主路由为 `/packagePetStudio/pages/index/index`，内部四个区域：

| 区域 | 已实现行为 | 与其他区域的联系 |
| --- | --- | --- |
| 小屋 | 当前宠物、等级、亲密、成长进度、三个家具位置、当前章节任务、生活记录入口 | 游戏经验推动成长；收藏摆进小屋；章节完成后小屋增加暖光 |
| 小镇 | 湖畔地图四处入口、四款独立游戏、每款六关 | 实际成绩、纪念物与关卡记录写入同一本机成长档案 |
| 收藏 | 三套装扮选择与试穿、确认穿搭、家具布置、固定价格小铺 | 确认后首页、聊天、游戏复用同一份适配穿搭；星光仅用于固定物品兑换 |
| 故事 | 三章任务清单、阅读、两种选择、故事页收集、兴趣方向 | 三款以上游戏与小屋任务交叉推进；每章首次珍藏获得 30 经验 |

闭环是「游玩 → 保存真实本局收获 → 成长/收藏 → 布置或换装 → 推进故事 → 再选路线」。普通退出未完成的游戏不会被当成通关；存档失败保留待保存结果，重试使用原局 ID。

## 2. 四款游戏的实际操作

| 游戏 | 实际操作与机制 | 六关的差异 |
| --- | --- | --- |
| 湖畔餐车 | 选单、点选或拖动食材、备菜、控火、装盘、出餐；顾客耐心、连击、焦锅清理、餐食冷却；90 秒营业 | 早餐、热汤、素食、蛋白补给、双份备菜、雨天终局；菜单与订单调度不同 |
| 食材合成局 | 5×5 棋盘四向滑动、同类合成、配方选格与交菜、一次撤销、暂停 | 食材等级、固定收纳篮、步数、配方顺序与目标不同；不能原地重复领配方 |
| 活力冒险 | 横向跳台场景；移动、跳跃、分岔、推箱开门、踏板、风向与休息/辅助路线 | 三类场景、六条关卡路线；机关和安全/收集分岔不同，叶纹滑板为外观道具 |
| 水岸寻宝 | 相邻节点移动、观察线索、水渠旋转、石板顺序、按住/切换收线、张力控制与行动点 | 六张地图的路线、线索、主线宝物与机关不同；节点收获有来源 ID，跨重进不会增加重复地标 |

旧餐车、旧冒险页面地址保留为跳转入口，进入新空间对应游戏；旧页面不再写另一份星光账本。

## 3. 成长、章节与本机星光

本轮没有开通云端代币，界面明确标注「本机星光」，与原有 AI 积分分别管理。

- 每个账号每天每款游戏第一次有效游玩奖励 6 星光，四款合计最多 24。反复游玩可以保存更好成绩和新收藏，不重复增加这项日奖励。
- 有效参与标准：餐车实际送出至少一餐；合成至少完成一次有效操作；寻宝至少移动两次且实际获得节点收获；冒险前进至至少 40 距离。冒险无人操作停在首个分岔的 25 距离，不领奖。
- 日常游戏经验每只宠物每天上限 20；亲密有每日上限，问候每天只加一次。首次珍藏章节的 30 经验独立于重复阅读。
- 星光是账号共享钱包；经验、亲密、通关、章节、路线地标与小屋摆放按宠物保存。装扮按账号、宠物 ID、形象标识隔离。
- 小铺固定价格：绿植 20、台灯 30、叶纹滑板 40、探险围巾 30。已购买不重复扣款；没有随机抽取，也不改变挑战战力。
- 本机日期回拨不重置已记录的当天奖励。当前是本机机制，不能声称具有服务端防篡改能力。

三章任务：

1. **灯亮之前**：发现三个不同水岸地标、完成一关餐车、摆好旅途卡。
2. **水岸失物**：完成寻宝第二关、完成一关合成、珍藏上一章。
3. **雨天的餐车**：完成餐车第二关、冒险第二关、珍藏上一章。

故事选择会保存并允许重读/改选；当前尚未改变后续地图或生成分支事件。职业兴趣为可自由切换的表现标签，尚未提供职业技能树。

## 4. 角色一致性与衣橱

`PetActor` 统一复用原程序精灵和照片宠物，始终保留当前选择的身份。原鬼鬼仍是眼镜、黑上衣、米色裤子的女性像素角色；用户的其他模板和照片不会被替换成鬼鬼。

动作能力由实际资源决定：原鬼鬼支持现有休息/行走帧；另一套已有精灵支持其自身眨眼、招手、观察和庆祝帧；照片角色仅使用其实际提供的眨眼/跳跃图。不支持的动作保留原角色，不能借用另一角色或将整体扭动称为完整肢体动画。

围巾目前仅适配原鬼鬼体型，颈部定位并跟随行走帧调整；其他体型显示待适配。试穿不立即改首页，确认后才保存共享衣装。首页用小尺寸服饰资源，不依赖用户已经访问游戏分包。隐藏/后台会暂停角色帧和照片动作计时器。

养生模式的原头像与悬浮宠物渲染分支保留；没有改八套均衡主题、健康分析、记录、榜单或周报显示策略。

## 5. 本机存档与兼容

- `pet_growth_v2:<account>` 保存共享星光、物品、回执与多宠物成长，使用递增版本拒绝旧页面快照覆盖。每次兑换/摆放/章节/结算均从最新持久化档案计算；回到页面刷新账本，保留当前游戏与待保存本局。
- `pet_loadout_v2:<account>:<pet>:<appearance>` 保存明确确认的穿搭。旧试穿偏好仅按原有账号+形象范围读取兼容。
- 每只宠物第一次迁移旧冒险进度时保留星光、经验、通关、物品、家具位置与已结算局 ID；只迁移一次，旧副本保持不动。读取异常不会用空档覆盖；写入异常不会删除旧档。
- 旧餐车账号最好成绩作为「账号历史」参考读取；新宠物成绩独立，不把旧账号成绩当作新宠物的通关或奖励。
- 普通「清除缓存」保留这些本机成长、衣装与旧恢复副本。清理图片/API 缓存不等于删除用户的游戏存档。
- 账号或宠物切换后，旧请求不覆盖新档案；旧局不写入新账号。账号读取暂不可用时暂停并提供页内重新确认/重试读取入口。

## 6. 本轮验收记录

规则与界面联动测试包括四款真实游戏引擎及其输入组件，另外覆盖迁移、失败重试、账号切换、章节、穿搭、异步宠物档案防旧响应覆盖、后台暂停。代码提交 `a4026605` 的强制暂存快照 Hook 已通过 TypeScript、相关 ESLint、全部 113 套 / 576 项 Jest、diff 与敏感文件检查。原生证据的无个人信息摘要见 `native-qa.json`。

微信开发者工具原生自动化已尝试真实账号读取、导航与截图。当前编译包实际连接 `https://api.healthymax.cn`，宠物档案请求失败；正式及开发域名健康接口返回 Nginx 502。此条件下不能宣布真实账号完整流程通过。

隔离检查仅临时替换宠物档案的只读响应，操作正常页面，不注入关卡成绩或星光。原生已验证新小屋、小镇四入口、合成准备界面、收藏布置、三章故事切换；随后通过真实按钮完成两款新游戏：合成两道配方取得 420 分/四个有效操作，寻宝实际解水渠并控张力打捞取得 397 分/三处地标。共享本机账本由 0 增到 6 再到 12 星光，只有两张回执，两个实际纪念收藏均在档案内。原鬼鬼精灵路径也在原生控件中确认。测试创建的本机档案经过前后严格比较后恢复，原接口也恢复。截图接口多次超时/失败，因此没有当前页面视觉精致度验收通过的结论。候选渲染图仍是设计目标。

开发态分包检查：新宠物分包约 1.36 MiB，在分包 2 MiB 限额内；现有主包与另一历史分包在开发输出中超限，不能将本轮 watch 输出直接视作可上传体验版的生产包。此次没有执行生产构建、上传小程序或启动/重启后端。

## 7. 后续实施阶段

按原报告继续推进以下事项，均尚未伪装为已上线：

1. 实际账号接口恢复后，完成真机完整章节、四游戏六关可玩性及视觉对照；逐关调整节奏与难度。
2. 补齐当前身份的完整肢体动作、更多体型衣装、动作过渡与物品专属图像；故事选择产生真正的后续路线和事件。
3. 接入 Go 服务端的权威星光账本、幂等回执、健康记录任务及跨设备同步，实施前先完成模型/迁移/测试，再执行批准的目标数据库迁移。
4. 单款真人匹配 PK 样板与成绩核验，再扩展其他玩法；客户端不生成假对手、假排名或假服务器奖励。
5. 更完整的职业、家具组合、制作配方、季节活动与长期收集，用真实留存/回访及健康记录指标评价，而不只看游戏停留时间。
