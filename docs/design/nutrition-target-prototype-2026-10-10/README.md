# 饮食方案本地交互原型

直接打开本目录的 `prototype.html` 即可体验。已请求在 Codex 右侧打开本地文件；打开请求返回 queued，尚未验证浏览器渲染。

可选静态服务预留地址为 <http://127.0.0.1:8768/>，当前没有启动。自动审批拒绝了本轮服务启动命令，仅返回 `blocked by policy`；已改用直接打开文件，没有绕过拒绝。

体验路径：

1. 首页一体营养面板右上角「目标」→ 选择休息日或训练日 → 自动回到首页，查看目标和剩余额度变化。
2. 目标 → 只调整今天 → 修改热量 → 碳水自动计算，蛋白质和脂肪保持 → 保存。
3. 我的 → 饮食方案 → 编辑、复制、新建、设默认或删除；列表也支持明确应用到所选日期。
4. 切到昨天或明天，查看历史快照和默认方案的区别。编辑、删除方案不会重写已经应用的日期。
5. 热量、三大营养素与微量营养共用一个面板。点击面板底部「营养概览 · 展开更多」，21 项指标在面板内部展开；点击「收起」折叠，不跳转新页面。展开区「管理目标」打开当天编辑。数据不足不当成 0；编辑方案时仍可继承档案或开启独立设置。
6. “我的 → 饮食方案 → 从预设创建”提供均衡日常、高蛋白、碳循环训练/休息组、地中海风格、DASH 风格。单套预设先看详情、编辑后保存；碳循环可以修改两天热量，一次添加两套。导入不自动应用到今天。

数字和饮食记录均为样例。浏览器仅保存本原型选择，不连接业务 API、不修改真实账号。圈子入口未展开；分析只演示所选日期使用相同目标。

微量参考值来自项目现有目标配置的示例档案，不是所有人通用的推荐量。钠/饱和脂肪按限制值展示；总糖和胆固醇仅记录，不能把总糖当作游离糖。输入最大值是演示数据校验边界，不是营养素的可耐受最高摄入量。地中海、DASH 包含食物选择侧重，不用一套固定宏量比例代表整个饮食模式。修改、复制、删除和按日应用同时覆盖宏量与微量快照。

旧版原型的本地选择可自动升级。修改 HTML 后需要刷新已打开的浏览器标签页。

视觉按现有首页的 Meal Orbit 源码重做：奶油底色、伙伴问候、周日期条、左侧热量圆环与右侧三大营养素、原位折叠区、深绿底部导航与中央拍照位。底图、圆环装饰、伙伴和 iconfont 均嵌入项目已有素材，可离线打开。圈子、拍照及快捷记录只保留已有界面位置，本原型聚焦饮食方案交互。

已用安装的 miniprogram-automator（weapp-devtools 的底层 SDK）尝试核对微信首页：appid 正确，原页面为圈子；首页读取 RPC 超时，恢复圈子返回成功。未改账号、API、业务数据或开发进程。HTML 的同面板折叠、日期目标、方案编辑与五预设交互经 jsdom 检查通过；浏览器像素和最终微信 UI 未验通过。

可编辑源文件：`../nutrition-target-ui-demo.html`。独立 HTML 使用已有 visualize 导出脚本生成，不新增依赖。

可选服务代码只绑定本机 127.0.0.1，允许 GET/HEAD 两个 HTML 路径。`stop-preview.ps1` 仅停止已登记的本次预览；先核对 PID、启动时间、进程名称和脚本路径。当前无本原型服务需要停止。

如需清理，先停止本原型服务，再删除本目录即可。源码和设计规格保留在上级目录；不要清理其他原型或共享开发进程。
