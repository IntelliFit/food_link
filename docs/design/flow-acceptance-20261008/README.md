## 后续复测：返回对照、动作运行与游戏操作

本轮继续使用原生开发者工具与 miniprogram-automator，没有改业务代码、健康记录、账号形象或钱包。环境记录：开发者工具基础库 3.15.2，automator 0.12.1；没有升级依赖或修改私有配置。

### 返回链路的范围与限制

| 检查方式 | 结果 | 证据 |
| --- | --- | --- |
| 从宠物页 SDK 打开书架，再 SDK 返回 | 页面栈与延后查询均正确回到宠物页 | `navigation-control.json` |
| SDK 直接打开隐私、饮水、运动页，再返回 | 三条路径均回到宠物页且延后页面栈一致 | `record-direct-control.json` |
| 成长入口触摸进入后，较快操作原生返回按钮 | 饮水、运动均未确认返回；随后正常恢复成长页 | `native-left.json` |
| 成长入口触摸进入后等待 7 秒，再 SDK 返回 | 饮水与运动各重复两轮，栈只有宠物页、成长卡存在、钱包 0 币/3 回执 | `care-return-ready-first.json`、`care-return-ready.json` |
| 等记录页视图出现、饮水 spinner 消失即 SDK 返回 | 页面约 1.58 秒已满足视图检查，但后续 9 秒内仍未确认返回 | `care-return-repeat.json` |

结论仅限于上述运行条件：较长等待后 SDK 返回可重复成功，较早返回仍不稳定；不能宣布返回问题已经修复，也不能把等待 7 秒变成产品强制延迟。代码检查没有发现记录页主动重新导航或覆盖 navigateBack 的逻辑，根因仍未确定。已向用户询问手动点击原生返回的表现，暂未收到回复。没有据此盲改登录守卫或健康记录逻辑。
