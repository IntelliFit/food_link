## 入口与操作

- 首页原营养面板的“目标”打开方案选择；方案名称也可进入。保留原热量圆环、三大营养素、同面板的微量展开／折叠。
- 在选择面板点“选用”，应用到首页正在查看的日期，保留食物记录并提供撤销。“只调这一天”保存独立日期目标，不修改模板。
- “我的 → 饮食方案”管理保存的方案，也可由选择面板进入。支持编辑、复制、默认和删除，最多20套；基础方案不占容量。

## 目标规则

1. 热量改变时保持蛋白质和脂肪参考值，碳水补差额；关闭自动碳水时由三大换算热量。不足以容纳蛋白质／脂肪时拒绝保存。
2. 脂肪显示上下限，进度与超量判断采用上限，推荐不因未补到脂肪参考值而扣分。上下限是用户计划，不是统一医学推荐剂量。
3. 微量默认继承个人基础目标，或独立填写19项目标；空的独立项目继承基础值。总糖、胆固醇仍记录摄入，不设置补齐目标；钠与饱和脂肪显示控制值。
4. 应用日保存4项宏量＋21项其他营养的完整快照。调整热量不同比缩放微量；仅修改当天热量时保留当天已经冻结的继承微量。
5. 修改／删除模板不改已有日期快照。默认选择从今天用于未单独安排的日期；编辑默认模板或修改其继承的基础值从明天生效。首次改基础值也保存今天的旧默认版本。
6. 撤销恢复操作前的完整目标，包含原来隐式使用的默认／基础方案。日期写入令牌和模板版本防止旧页面覆盖新修改，同用户事务锁保证双方案创建、容量和日期写入的一致性。
7. 缺少历史快照的旧日期标为“历史参考”，不会将当前基础参考值冒充当时真实计划。旧每日目标保留原宏量，微量标为参考。

## 常用预设

均衡日常、高蛋白、碳循环、地中海风格、DASH风格共五个入口。先查看食物方向，再调整并创建；创建不自动改今天。碳循环按训练／休息顺序原子创建两套。

数值基于用户基础目标：高蛋白用基础蛋白上调20%作为编辑起点，碳循环用热量110%／90%作为起点，均非个人处方。地中海和DASH保留基础数值，提供食物结构提示，不把固定宏量比例或强化微量剂量冒充完整饮食模式。

## 后端与下游

新增领域、仓储、服务和处理器位于 `backend/internal/user/` 的 `nutrition_plan*` 文件。

| API | 用途 |
| --- | --- |
| GET /api/user/nutrition-plans | 基础目标、方案库、默认ID |
| POST /api/user/nutrition-plans | 创建一套或训练／休息两套 |
| PUT /api/user/nutrition-plans/:id | 带revision修改 |
| DELETE /api/user/nutrition-plans/:id | 归档；当前／待生效默认需先换默认 |
| PUT /api/user/nutrition-plans/default | 选择默认 |
| GET /api/user/nutrition-plans/day/:date | 解析日期有效目标 |
| PUT /api/user/nutrition-plans/day/:date | 选择、当天微调、撤销或恢复默认 |

全部使用现有JWT鉴权及当前用户隔离。方案操作不创建饮食记录、补剂记录或增加摄入。账号注销同时清理方案与默认版本，新表带用户删除级联外键。

首页按查看日期解析目标；推荐和聊天的个人资料按今天解析；周／月统计按每个日期解析，只累计有饮食记录日期的计划目标，另列摄入与计划差值，保留原估算消耗口径。摘要指纹包含目标版本，目标修改会刷新首页与推荐。

微量评分沿用项目已有标准形式、证据覆盖和可比较规则，接入目前标准化引擎能够比较的项目；不声称已将面板21项全部改造成临床模型，也不将个人计划阈值解释为缺乏诊断。预设的食物结构提示不等于已经实现完整地中海／DASH食谱约束引擎。
