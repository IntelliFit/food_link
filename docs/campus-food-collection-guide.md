# 食堂照片采集与录入说明

## 为什么单独建立采集层

现有 `public_food_library` 适合发布一条已经整理好的菜品：名称、食堂、窗口、价格和图片相对明确。线下扫档口得到的原始材料更复杂，常见情况包括：

- 一张窗口全景同时包含招牌、菜单牌和若干食物；
- 同一窗口早、中、晚供应不同内容；
- 自选菜、套餐、按重计价、麻辣烫等无法用“一个菜 = 一份固定价格”表达；
- 只拍到菜单或价签，没有食物图；也可能只有食物图，不知道名称或价格；
- 园区食堂不属于校园目录，但仍有园区、食堂、楼层、窗口层级；
- 当前材料不完整，后续需要管理员或普通用户继续补图、补名称、补价格。

因此本次新增“采集批次 + 采集条目”，先忠实保存现场证据和未知项，审核整理后再发布到公共食物库，避免为了满足旧表必填项而编造数据。

## 助理录入流程

后台进入“食堂采集”：

1. 新建一个采集批次，填写学校/园区、食堂、楼层、默认窗口、拍摄日期和采集人。
2. 校园场所优先从现有目录选择；园区食堂直接填写园区名、区域名和食堂名。
3. 一次选择多张已经切分的照片。系统按文件生成多条记录，也可以继续给同一条追加照片。
4. 只有窗口全景或菜单牌时，选择对应记录类型和图片类型，不要强行填写菜名。
5. 没拍到照片但确认现场有这个菜或窗口时，点击“添加无照片记录”。
6. 价格不确定就保留“未知”，把价签原文写到“价格原文”；不要根据结账总价反推单菜价格。
7. 保存批次。上传中断后再次保存会复用已经成功上传的图片，同一个客户端批次标识也会防止重复建批次。
8. 后续可在“最近采集批次”逐条编辑补充。保存只更新后台草稿；名称、图片和价格补齐后，点击“提交上线”才会同步到公共校园食物库并在小程序显示。

已上线条目再次编辑时，线上旧版本继续可见，后台状态变为“有修改待上线”；再次点击“提交更新”后，小程序才切换到最新版本。

单批次最多 200 条，每条最多 6 张图片，单张图片最大 20 MB；支持 JPG、PNG、WebP、HEIC。

## 字段选择

### 记录类型

| 类型 | 用途 |
| --- | --- |
| 菜品 | 可以相对明确地指向一道菜或一份成品 |
| 菜单项 | 只从菜单牌、吊牌或价签识别到的名称 |
| 窗口概览 | 横向大窗口、档口正面或暂时无法拆到具体菜 |
| 套餐/组合规则 | 几荤几素、任选若干菜、拼盘等组合售卖 |
| 自选食材 | 麻辣烫、自选称重区的一种食材或整片食材陈列 |

### 售卖形式

固定份、自由选菜、套餐组合、按重量、麻辣烫、自助、现点现做、零售、混合、未知。窗口默认值会自动带入每条记录，单条仍可覆盖。

### 餐次与窗口形态

餐次支持早餐、午餐、下午、晚餐、夜宵、全天和未知，可多选。窗口形态支持小窗口、标准窗口、大窗口、连续长档口和未知。

### 价格

| 类型 | 示例 |
| --- | --- |
| 固定价格 | 鸡排 2.2 元/两；整份盖饭 15 元/份 |
| 价格区间 | 约 8–15 元 |
| 按重量 | 麻辣烫 2.98 元/100g |
| 套餐组合 | 两荤一素 12 元 |
| 时价 | 当天价格变化 |
| 原文描述 | “素菜 1 元/份”“荤菜按收银结算”等无法完全结构化的文本 |
| 未知 | 照片和现场信息都无法确定 |

价格数值和原始文字可以同时保留。对于多人拼菜或最终结账价，不把总价误记成某一道菜的固定价格。

### 图片证据类型

菜品实物、菜单牌、窗口正面、价签、自选食材陈列、小票、其他。数据库保存 COS object key，接口返回时解析为 CDN 地址。

## 示例照片建议

- 麻辣烫宣传牌：记录为“窗口概览”或“套餐/组合规则”，图片类型“菜单牌”，售卖形式“麻辣烫”；汤底、酱料等文字先放入“照片可见文字”。
- 老北京炸鸡窗口全景：记录为“窗口概览”，图片类型“窗口正面”，再按吊牌拆若干“菜单项”。
- 单独拍清楚的吊牌：记录为“菜单项”，保留名称、标价、单位和原始文字；没有实物图也可以保存。
- 食物陈列：能分清不同菜时切图后逐条录入；暂时分不清时先建一条窗口概览，后续再拆分补充。

清华校园目录中的正式食堂名称应以现有目录为准，例如“紫荆园”“桃李园”。如果现场口述或群聊使用“紫金食堂”等别称，可写在备注中，不要覆盖目录正式名称。

## 上线前置条件

本功能新增数据库表 `campus_food_collection_batches` 和 `campus_food_catalog_items`。必须先确认 `backend/config.yaml`/环境变量指向的目标数据库，再从 `backend/` 执行：

```bash
go run ./cmd/migration -config-dir .
```

随后部署 Go 后端和 Admin。未执行迁移时，后台页面可以构建，但保存和查询会因数据表不存在而失败。

当前阶段提供管理员采集入口，优先保障助理批量录入。数据模型已保留 `contributor_user_id` 和缺失字段状态，普通用户补充入口可在下一阶段接入；当前小程序里的单菜分享流程不受影响。
