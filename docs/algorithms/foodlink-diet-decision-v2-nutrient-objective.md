# 食探饮食决策 v2：健康优先、营养状态驱动的优化规格

日期：2026-10-08。状态：本稿保留目标设计；首版 v3 已在 dev 实现并完成小马哥两日只读对照，尚未发布。实际覆盖、旧版保留、公式与限制以 [v3 实现说明](foodlink-diet-decision-v3-implementation.md) 为准，不能把本稿全部远期要求当作已实现。

用户本轮明确：运动先不做；当前统一以健康为首要目标，但需要个体化、动态的综合决策，不能只比较热量和三大营养素。本稿收敛这一方向，不覆盖既有餐食点单、费用和安全护栏，不改积分规则。

## 1. 当前能力与真实缺口

当前 v2.1 已有真实候选召回、点单约束、个人宏量目标、食物组线索、曝光/跳过反馈及部分分析联动。它是可继续迭代的底座，不是完整的营养优化模型。

源码证据：

- `backend/internal/health/domain/health_domain.go` 的 `DietRecommendationCandidate` 只有热量、蛋白质、碳水、脂肪的结构化数值。`DietRecommendationFoodItem` 只有名称、份量描述和来源 ID；原始营养字段不会由它直接传到评分器。
- `backend/internal/health/repo/stats_repo.go` 的候选转换读取四项宏量及证据摘要，没有传递微量营养向量。不能因为源库/分析记录中可能有维生素，就认为它已经影响推荐排序。
- `diet_decision_engine.go` 的健康匹配仍是四项宏量区间评分；综合效用为健康 55% + 可执行性 30% + 启发式可信度 15% - 风险惩罚，再加食物组奖励。
- `diet_decision_basis.go` 使用四类食物组的菜名/食材线索，有界奖励为工程参数；不是食材克数、微量含量或完整膳食质量指数。
- `stats_service.go` 汇总纤维、钠、钾、钙、铁、维生素 A/C/D，但参考值仍是固定展示值。`nutritionagg.SumMetrics` 初始化缺失指标为 0，因此仅凭汇总结果不能区分真实零与没有字段。接入决策前必须补证据覆盖，而不是把这些数字直接当个人营养缺口。

此外，首页规则最终选餐和聊天模型选择 ID 的路径还没有完全统一。本规格要求最终选择使用同一政策；不能把这一要求说成当前事实。

## 2. “统一健康优先”不等于“所有人吃一样”

统一的是评价原则和安全边界；个体化的是适用参考、已记录摄入、食物模式、可选菜单与现实约束。

分清三类变化：

| 变化 | 例子 | 当前设计处理 |
| --- | --- | --- |
| 营养状态变化 | 午餐已吃、近期食物结构变化、补录了一餐 | 重新计算候选的边际营养价值 |
| 个人条件/明确目标变化 | 年龄、生理条件、保存的计划、增肌/减脂目标 | 按适用且审校的规则更新目标，不重复奖励同一营养素 |
| 个人价值偏好变化 | 愿意多走路、口味、愿意花多少钱 | 预算/时间先界定可行集合；健康近似等价时参与排序，不擅自降低安全或健康标准 |

现在不做“自动学习每个人愿意牺牲多少健康”的自由权重系统。未来若支持不同政策，必须由用户明确选择并显示区别；点击率不能替代健康价值，也不能从一次没点餐推断长期不喜欢。

## 3. 决策对象：真实整餐组合和可购买份量

用 `x_i` 表示候选菜品 i 的购买份数。取值只来自实际销售规则，例如 0 或 1 份；只有明确支持半份/小份时才允许相应离散值。

可行集合 F 包含：过敏/忌口已核对、位置可达、营业信息可用、完整费用不超过预算、份量和点单依赖成立。半份、去酱、加菜、库存、排队时间和营业状态未知时不编造。过敏原未知不能视为已证实安全；可行状态应区分已核对、未知和违反。

用户的“饮食半径”不是单纯公里数：它还受能否进入、步行时间、营业、预算、整餐可购买性和用户时间影响。没有符合条件的方案时说明冲突，不用配菜拼出虚假完整低价餐。

营养预测的基本关系：

`本次进食后的已知营养量 z_j(x) = 当前已知摄入 I_j + Σ_i (购买份数 x_i × 每份营养量 n_ij)`

`n_ij` 必须有对应份量、单位、来源和缺失状态。每 100g 数据需要份量转换；原料生重、熟重、可食部分、烹调损失及额外油盐不可混用。

## 4. 营养目标不是每个成分都越多越好

| 维度 | 进入模型的内容 | 处理方式 |
| --- | --- | --- |
| 能量与宏量 | 能量、蛋白、碳水、脂肪；有依据时含脂肪质量 | 个体计划范围，过少和过多分别处理，不能把总脂肪越低越健康 |
| 首批扩展 | 膳食纤维、钠、钾、钙、铁及 A/C/D | 按可验证数据覆盖与人群规则分批进入，不因已有固定展示值就视为个体参考 |
| 后续扩展 | 锌、镁、叶酸、B12 等；饱和脂肪、游离糖等饮食成分 | 先补数值、形态、来源和适用参考；缺数据不填 0 |
| 整体膳食 | 蔬菜、水果、全谷、豆类、奶类、鱼等结构、份量及近期分布 | 食物组与营养向量共同使用，不以添加维生素就判整餐健康 |
| 专项目标 | 有依据的营养支持条件 | 先改适用计划，不凭空创建“抗衰营养素权重”或把支持分当实际效果 |

上述是一批数据需求，不表示每个字段已收录或每种特殊人群都能自动处理。膳食纤维并非维生素/矿物质，但同样不能遗漏。

中国产品优先使用逐项核录审校的中国 DRIs/膳食指南。NIH 的 DRI 定义用于理解参考值类别，不把美国数值直接替换中国参考。[NIH 参考值定义](https://ods.od.nih.gov/HealthInformation/nutrientrecommendations.aspx)

RNI/RDA 是膳食计划参考，不是低于它就已患缺乏；AI 是另一种参考，不能套用同一不足概率。UL 不是应当接近的目标，而且具体规则必须区分人群、营养形态和食物/补剂来源。并非所有营养素都有可用 UL；钠等指南限制也不能伪装成同类毒性上限。

WHO 的健康饮食框架同时强调充足、平衡、适度和多样性，并包括纤维、脂肪质量、糖、钠及维生素/矿物质。因此“只匹配四项宏量”不能当完整健康评价。[WHO 健康饮食](https://www.who.int/news-room/fact-sheets/detail/healthy-diet)

## 5. 健康优先的优化，而不是把所有价值随意加起来

建议保留多维营养损失向量：

`D(x) = [能量/宏量计划偏差，营养充足性计划偏差，应限制成分偏差，膳食结构偏差]`

一个可实现的充足性计划损失示意：

`d_j(z) = max(0, (r_j - z) / r_j)^2`

其中 `r_j` 是适用规则产生的**计划参考**。达到参考后该项不再继续奖励多吃。此式是工程规划损失，不是缺乏诊断、疾病风险或临床验证曲线；不能不加区分地用于 AI、单日记录或所有特殊人群。

能量/宏量使用适用范围的双侧偏差；限制项使用其自己的上侧偏差与时间/来源规则。不是给所有营养素统一设置“RNI 到 UL 的健康区间”。先消除重复计数：例如增肌与力量共用蛋白目标，不因此把同一蛋白缺口奖励两次。

选择政策建议：

1. **安全与实际可购买性**：仅对符合必要条件的方案评分，未知证据单列，不作安全承诺。
2. **营养优先**：在相同证据口径下剔除明显被另一方案全面优于的选择；评估各维计划偏差，避免一个维度的过量被另一个维度的高分抵消。必要的边界先作条件，不全塞进加权总分。
3. **近似等价方案中选可坚持的**：健康差异没有可靠证据或处于经校准的等价范围时，再比较完整价格、距离/时间、明确偏好和合理轮换。

具体可表达为：先在 F 内最小化经审校的营养计划损失 L，得到 `L_min`；再在 `L ≤ L_min + ε` 的方案中选择执行成本较低的。ε 需基于数据精度和比较实验确定，不预设“差 5 分无所谓”。来源、覆盖差异过大时不能硬算 L 决胜，应降级为有证据的局部比较。

健康损失内部仍可能需要权重，但权重只在可解释的营养维度间分配，属于可版本化、需评测的产品参数；不是医学定论。可以保留帕累托非劣候选展示权衡，不把“帕累托”一词当科学正确性的证明。

三张卡不应分别意味着“健康/便宜/综合，所以允许后两张明显不健康”。它们应在合格的营养方案中提供不同食材、做法或执行便利；候选不足时不凑数，取舍要说明。

## 6. 动态来自状态和边际价值，不必一开始就学习权重

容易理解的效用形式：

`营养计划改善 Δ(x | s_t) = 进食前的计划偏差 L(s_t) - 进食后的计划偏差 L(s_t ⊕ x)`

同一份菜在不同状态下价值不同：已吃够蛋白时继续增加蛋白不会无限加分；营养数据支持的纤维/钙计划缺口可能变得更重要；已知钠摄入偏高时高钠方案的优先级下降。这种变化可由状态更新自然产生，不需要大模型每次临时编造权重。

采用适合各指标的时间窗：日内供能和剩余餐次、近期有充分记录的食物结构、通常摄入评估分开。7 天只是可选的工程观察窗，不是能证明某人缺某营养素的临床门槛。一天低于参考不等于缺乏；不能把未录入的早餐当 0，也不能要求晚餐把一周缺口一次吃完。

若考虑后续餐次，可规划“这餐 + 后续可行餐”的组合，执行后只更新确认摄入并滚动重算。未来菜单未知时不能假定它一定能补足。只有单餐优化时，明确它没有求解全天或长期全局最优。

长期个人价值学习另立后续版本：明确偏好、实际选择和确认摄入分开；学习口味/执行成本，不自动学习突破安全规则。当前 selected 记忆不等于已经实现此能力。

## 7. 缺失和不确定性必须进入模型

每项营养观测建议合同：

`key, value或区间, unit, basis, portion, source_id, source_type, nutrient_form, source_scope, observed_at, status, coverage`

- 区分真实 0、未知、部分已知与估计；汇总保留已知小计和覆盖信息。不以“有饮食记录的天数”为所有营养素的完整分母。
- 同一批方案的比较使用相同可比较指标；未知钠不能胜过已知含钠，少填字段不能获得健康优势。知道部分营养不等于需要完全排除整餐，但不能称它微量营养最优。
- 有有依据的区间时，充足性参考较低端、限制项参考较高端，作敏感性检查；区间无校准时不能称统计置信区间。缺依据时标未知，不能随手造范围。
- 菜名/照片只能产生食材线索或标注的估计，不能可靠证明实际加盐、份量或全部维生素。能获取真实配方时，优先食材克数、对应数据库、熟制/留存及实际份量校核。
- 已确认补剂摄入纳入相关营养来源；标签、形态和适用限制分开。不能为了让分数好看自动建议补剂。
- 缺数据影响的是“能下多强的结论”，不应混进健康分使补资料凭空改善身体。健康适配、执行成本、证据质量分别返回。

## 8. 落地顺序与验证

优先复用现有 health domain/repo/service 和 preview/chat/stats，不先新建算法微服务。

1. **营养数据合同**：补候选每份营养向量及缺失/来源，从原始 items 和可信资料映射；重构聚合的未知/覆盖表达。核对首批中国参考规则，不沿用固定显示值作个人阈值。
2. **共用状态和损失模块**：同一目标、同一证据口径供分析、首页与聊天使用；健康优先和可行性明确分层，模型从引擎合格方案中解释/交互，不自由重定义健康权重。
3. **真实餐食组合与份量**：先在有限候选与真实销售份量上枚举/剪枝，报告召回与搜索边界；规模需要时再用约束求解器。不因技术名称复杂就宣称全局最优。
4. **对照评测**：与 v2.1 同快照比较，不只看点击或推荐分。再进行真实多餐体验验证。

必要用例：同宏量但已核实钠/纤维不同；蛋白达标而钙/纤维计划仍需改善；缺失微量不当 0；补剂与食物来源限制不同；饮食未完整记录；今日已超目标；多个目标共用同一营养维度；预算内无合格整餐；菜谱生熟/份量不同；价格更低不能抵消明确营养劣势；相同快照首页/聊天/分析依据一致。

记录安全/预算/点单约束违反、营养向量覆盖、缺失处理正确性、被支配方案比例、单项恶化和整体计划改善、实际可购买/确认摄入、解释与评分一致性。营养计划改善只是算法与记录层面的结果，不等同临床疗效。

本轮只交付设计与范围确认：未改业务评分、UI、数据库、模型调用、进程、积分、测试或发布。运动优化延后；读取已存在的个人消耗估算作为饮食输入，不代表开始开发运动决策。
