## 现在怎样选餐

1. 读取个人已保存目标、过敏/忌口、当前已记录摄入、近期食物组、真实候选与完整点单条件。
2. 保留候选及组合餐的 15 项扩展营养证据，区分真实零、完整记录、估算、部分小计和未知。组合中的未知配菜继续是未知。
3. 按适用年龄、性别、健康条件和已保存计划构造营养参考。年龄支持日期和 PostgreSQL 投影的 ISO 时间格式。孕哺/肾病等已标记特殊条件不套通用成人规则。
4. 比较候选餐后的营养计划偏差。达到某项充足性计划后，不再因为继续增加该项而加分；钠、饱和脂肪和游离糖比较规划限制。没有当日记录时使用本餐计划份额，不能解释成用户今天摄入为零。
5. 沿用 v3.1 的逐位置有界营养集合：当前可选池最高营养分减 5 分，再让实际曝光、近期重复、菜式与食堂多样性影响选择。5 分是待校准的工程容差，不是临床等价界限。用固定阈值而非两两 epsilon 比较；过敏、预算等硬约束仍不放松。公开菜单优先，历史至多一个补充。v3.2 允许模型在有界候选内终选，服务端复核，失败回退规则（见末节）。
6. 结果带版本、比较过的营养项、数值与单位、计划前后损失、缺失原因及参考来源。分析页面共享目标和营养状态依据；原有全部健康指标与图表没有被替换成这个餐食评分。

本版内部工程公式：

`充足性偏差 = max(0, (计划量 - 已知量) / 计划量)^2`

`限制项偏差 = max(0, (已知量 - 规划限制) / 规划限制)^2`

能量与宏量采用双侧区间偏差；能量权重 2，其余宏量各 1。存在可比较扩展项时，营养适配为宏量适配 60% + 扩展项平均计划适配 40%，另有最高 5 分的近期食物组线索奖励。缺失项采用本轮可比较候选的保守损失边界，不伪造营养克数；本轮完全没有数据的项不参加评分。原版“只有完全同分才能轮换”导致重复推荐，已由上述 v3.1 有界选择代替。公式、容差和缺失边界均未经临床或用户效果校准，不是健康概率、缺乏诊断或全局最优保证。

## v3.1 来源与可执行性修正

- 首页 preview 支持可选 `school_names`（最多 3 所），复用公开学校解析/菜单检索，不要求学生身份，不写个人档案，也不捏造 GPS。明确目的地覆盖附带定位/档案范围；无明确地点时仍走现有实时定位或档案/历史退路。**本轮未新增首页选校 UI，也未把特定学校硬编码进某个账号。**
- 现代菜单查询按需读取已有采集表的 `meal_periods`、售卖份量、计价模式、价格原文和供应状态。已知餐次先于菜名启发式；已知停售/暂不可售不作为新推荐。未知时段不当已验证营业。早餐检索在分页前加入餐次线索，避免被普通午晚餐截断。
- 历史候选保留 `meal_type` 与 `entry_type`；上午/下午加餐不直接冒充三顿正餐，早餐不机械复用历史午晚餐。文字标签由“吃过”改为“饮食记录”或“食谱录入”，保存记录不等于核实吃过。
- 模糊聊天不因当前时钟自动加上硬早餐限制；问原菜来源/数值的追问不被早餐名称启发式改成另一餐。

## 营养参考与边界

注册表保留纤维、钠、钾、钙、铁、镁、锌、A/C/D/E/B12、叶酸、饱和脂肪和游离糖。

一般成年人使用 [WHO 健康饮食](https://www.who.int/news-room/fact-sheets/detail/healthy-diet) 的纤维、钠、钾及脂肪/糖能量比例规划。18–49 岁一般健康人群的首批中国参考逐项取自以下官方表格，来源类型分别保留 RNI/AI：

- [常量元素 WS/T 578.2—2018](https://www.nhc.gov.cn/wjw/yingyang/201805/f2c614be95fe41dba8123c23a6e6fb55/files/1739783539207_73894.pdf)：钙、镁。
- [微量元素 WS/T 578.3—2017](https://www.nhc.gov.cn/wjw/yingyang/201710/ef2d42ee35894a46b7726457d08d7e2d/files/1739783538029_71556.pdf)：铁、锌的性别参考。
- [脂溶性维生素 WS/T 578.4—2018](https://www.nhc.gov.cn/wjw/yingyang/201805/3dcd74635d8e40bcb5d834d3b2f66964/files/1739783549670_23371.pdf)：A、D、E。
- [水溶性维生素 WS/T 578.5—2018](https://www.nhc.gov.cn/fzs/c100048/201805/e821444378d64bafa7283779631096ce/files/1733125378304_81397.pdf)：C、B12、叶酸。

这不是完整 DRIs 2023 实现。E 仅接受明确 α-TE 字段，叶酸仅接受 DFE，总糖不代替游离糖。维生素 A 的 RAE 不等于预成型视黄醇，未按总 RAE 擅套该形态的 UL。本版没有完整补剂、药物和所有营养形态的 UL 安全规划；不得用于补剂处方或宣称全部摄入安全。高分也不证明钠或饱和脂肪均达标，推荐理由会提示已知的规划取舍。

整体膳食仍为菜名/食材线索，尚非按克数计算的完整 CHEI。三张卡为互替方案，不是联合优化的全天食谱。营业库存、早餐能否供应某历史午餐、当前价格与位置，必须来自另有的可购买证据。

## 按具体用户回放

在 `backend/` 下：

```powershell
go run ./cmd/diet-replay --self-check --output ../.local-state/current-task/diet-v3-20261008/self-check.json
go run ./cmd/diet-replay --user-id <精确用户ID> --date 2026-10-08 --output ../.local-state/current-task/diet-v3-20261008/user-replay.json
```

昵称必须唯一才允许查询；推荐传精确 ID。可使用 `--nickname` 作身份交叉校验。`--budget` 仅用于明确指定的情境，缺省不猜预算。

可加 `--schools 清华大学,北京大学` 传入本次明确就餐范围；`--simulate-exposure` 顺序模拟看过前序 v3 卡片，两个版本共享相同曝光输入。曝光只用于去重，不视为选中/已吃，也不修改营养余量。默认独立回放和连续曝光回放应分别保留，不能将两者冒称全天联合食谱。`--audit-records <本人记录ID>` 用于源记录核对，`--audit-breakfast-menus --schools ...` 用于菜单原始份量/时段审计，均保持只读。

工具建立 PostgreSQL repeatable-read **只读事务**，再调用实际服务：默认目标日和前一日，各自零点截止，早餐/午餐/晚餐分别运行 v2.1 和 v3，共 12 次。摄入时间和创建时间都必须严格早于截止时点，排除目标日摄入、后来补录、未知创建时间及其他用户记录。两版本的个人/饮食快照和候选池哈希必须相同。没有聊天、积分、摄入或推荐反馈写入；模型调用默认关闭，v3.2 仅显式 `--model-judge` 时开启。

个人档案、菜单及价格仍是当前版本，早期饮食记录的后续编辑也没有修订历史；因此这是“隐藏目标日饮食”的受限反事实回放，不是完整的历史环境重建。报告可能包含敏感个人资料，应保存在 `.local-state`，不公开提交。

## v3.2 完整目录与大模型终选（2026-10-08，未发布）

以下覆盖上文 v3.1 的“每校最多 300 条”和“模型最终必被规则改选”，不修改 v3 营养公式，不引入运动推荐。

1. **范围先定，再完整读库**：首页使用用户授权且有效的实时定位，默认 5 公里，包含校内与校外已发布菜单；明确学校查询优先于附带位置。没有定位时保留清楚标注的档案/历史退路，不捏造用户坐标。内部按 ID 游标每页 100 条扫描到匹配总数，无 300 条截断；超时/目录变化/错误返回不完整回执，不能把“未读完”说成“附近没有”。外部列表分页接口的上限不变。
2. **硬条件与证据**：继续过滤预算、忌口命中、已知停售、餐次及整餐点单依赖；读取已有菜单的星期、餐次、供应备注、份量和营养来源。供应未知仍明确待确认，不能保证入校、库存或过敏安全。模型估算、份量空白、低价主餐信息可疑等产生最高 8 分的证据扣分，不擅改原价格与克数。
3. **有界取舍**：每个位置先取剩余候选最高营养适配分减 5 分内的集合，然后比较便利、口味、既有菜式/曝光惩罚、同食堂跨餐曝光（每个餐次 3 分，最高 12 分）及未来搭配。统一“桃李园”和“桃李园简约餐厅”的明确名称后缀，避免误当完全不同食堂。没有强制学校或食堂配额，营养差距大时仍可能重复。
4. **未来餐次条件规划**：每个当前备选单独假设吃完，尝试后续午/晚餐。未来每餐最多 36 个已筛选候选，束宽 4；组合损失为宏量 60%＋可比较扩展营养 40%＋重复惩罚，反向影响本餐排序最多 3 分。已记录摄入和假设计划独立，不写饮食记录、不虚减真实余量。它是受限搜索，不是完整菜单组合的全局最优，也不保证全天达标；请求到期会停止规划。
5. **模型做最后的近似优劣判断**：完整库先参与规则计算，再将最多 36 个分散来源且在容差内的候选提交模型，提供菜单描述、份量、时段、距离、价格、个人记录与营养取舍。模型只能返回候选 ID，服务器重新检查完整池中的逐位置容差、去重和可行性；8 秒超时或无效输出回退规则并记录。聊天检索同样保留完整可行池，模型有效选择不再强制被规则覆盖。首页未来餐规划尚未接入聊天的所有工具分支。
6. **可解释回执**：返回目录匹配/检索条数、最终方法/回退原因、候选得分及证据扣分；首页“推荐依据”展示范围、方法、证据缺口与条件搭配。`ai_used` 仅代表模型参与，不等于模型最终决定；前端按 `selection_audit.method` 判断终选方式。

权重、5 分容差、36 候选及束宽 4 都是工程参数，未经临床或用户效果验证。公开菜单“全扫描”不等于现实世界“全收录”：新增商家/菜单、当天售卖餐次和可靠份量仍需持续采集核实。
