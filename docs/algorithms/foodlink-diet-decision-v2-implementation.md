# 饮食决策 v2.1：第一阶段实现与交付边界

## 已实现

- 首页使用按用户/日期/餐次稳定的候选种子，按窗口分散召回，最多读取 3 × 100 个附近或学校候选；经过完整点单、营养证据、过敏/偏好等已有检查，再挑选最多三个不同方案。不是生成 300 个菜，也不承诺不足时凑齐三个。
- 优先两份可定位的公共餐食，历史最多一份且不强制占第三格；无定位/学校/公共候选时明确降级。实时 GPS 有效时不再额外奖励常驻学校。
- `meal_recommendation_memory` 记录签发、有效曝光、换组和选择。签发不算曝光，曝光为首页可见且卡片至少 50% 进入视口、停留 600ms；只记录当前卡。换组是本餐临时跳过，不是永久不喜欢；选择不等于摄入。
- 读取最近 7 天最多 600 条有效交互。同一上下文刷新稳定，跨日/上下文对见过的餐食和同类菜降权。用 source ID 与规范化食材指纹去重。新曝光接口只接受当前用户在过去 48 小时签发的选项，重复报告幂等。
- 内存表不保存原始健康档案、聊天或 GPS；上下文使用散列。活跃用户再次生成时惰性清理自身超过 14 天的行；不是全局定时删除，休眠账号旧行暂保留，后续全局保留期清理尚未实现。
- 首页营养目标解析、推荐/聊天的决策目标和分析页新增 `diet_decision_basis` 共用一处解析。个人保存目标优先；默认目标明确为应用值，不冒充 DRIs。临时聊天目标覆盖档案主目标，同时保留专项关注；今日已超标也不抬高原目标。
- 近 7 天至少 3 天有具名食材，才分析已记录饮食中未出现的食物组线索。菜名不是重量或完整食材证明；“鱼香”口味不直接当鱼类。食物组优先级参与排序，也成为分析页行动建议；原非饮食行动保留。
- 首页保留三张滑动卡与“聊聊这餐”；新增“换一组”和二级“为什么推荐/复制来源”，不在主卡展开科学长文。新入口按后端决策版本显示，旧后端不承诺换组能力。
- 自定义关注评分版本升级：作息填写不再提高力量支持分，皮肤描述/水记录不再提高皮肤分。缺少可靠专项评分或证据时显示暂不评分；旧版分数不可直接比较。力量仍是标明权重的应用支持参考，不是实际力量成绩；至少三个饮食记录日、体重、消耗估算和训练记录才显示，条件是工程数据门槛而非临床标准。不可评分项不进入综合分；不为其显示预计加分。

## 科学边界

实际启用的来源是《中国居民膳食指南（2022）》的食物多样与合理搭配原则，附版本、来源、作用范围和缺失说明。食物组 +5、曝光/同类/场所惩罚、多目标权重均为工程排序参数，不是医学阈值或验证过的疗效。

本次**未**完成 DRIs 2023 分年龄/性别/生理期数值表、完整 CHEI、DASH 专项评估、训练处方、个体血糖或代谢预测，也未重做分析页原有全部核心指标。不得宣传“已融合所有前沿模型”或“临床验证的个人健康分”。后续需逐条核录来源与适用条件、接入缺失数据，再独立验证。
