# 补剂服用记录同步圈子

补剂摄入使用独立的 `supplement_intakes` 数据源，圈子直接读取记录，不额外创建圈子帖子。动态类型为 `supplement_intake`。

新记录保存并通过内容审核后，按现有公开资料、好友关系及拉黑规则出现在圈子。列表和详情展示实际服用时间、名称、剂量及本次成分含量；成分含量为每份快照含量乘以服用份数。列表最多展示三项成分，详情展示全部。不把补剂显示为餐食，不显示无意义的零热量、蛋白质等餐食摘要，也不从新瓶身标签回填历史快照。

私人备注不随动态返回。数据库升级前已有的摄入记录默认隐藏，防止此前的私人记录因升级自动公开；新记录由服务显式写入 `hidden_from_feed=false`，仍受资料公开设置约束。历史记录的补发入口尚未实现。

支持补剂筛选、详情、点赞、评论、互动通知及举报处理。作者可从圈子隐藏动态，保留营养统计；删除服用记录会移除对应动态并通知首页刷新。补剂柜新增和删除服用记录时通知圈子刷新。补剂快照不可在圈子编辑。

## 发布顺序

先确认并获得目标非本地数据库迁移授权，再在 `backend/` 运行：

```powershell
go run ./cmd/migration -config-dir . -only-supplement-feed
```

该迁移新增 `SupplementIntakeDO.HiddenFromFeed`，并更新四张互动表的稳定命名 target type 约束。重复执行安全；不依赖手工 SQL 修库。常规全量迁移也使用同一份字段与 target type 定义。

迁移成功后再发布后端，最后上传包含新卡片和筛选的小程序及发布后台。后端服务启动时不自动迁移；旧结构部署新版后端会导致圈子查询缺列。本轮尚未执行非本地迁移、提交、推送或发布。
