# 校园食堂专区产品需求文档 v1.0

## 1. 一句话概述

在现有公共食物库、手动记录、圈子和赚积分体系基础上，新增“校园食堂”场景，让用户可以浏览、上传、记录和分享高校食堂菜品，并把**学校/食堂/窗口、价格、图片、份量和营养估算**作为核心信息展示。

## 2. 背景

`food_link` 目前已经具备食物识别、手动记录、公共食物库、圈子动态和赚积分等能力，但这些能力还没有形成一个足够强的传播场景。

高校食堂是一个非常适合作为冷启动传播抓手的场景：

- 学生每天高频吃食堂，记录需求真实。
- 食堂菜品通常有固定位置、固定价格和相对稳定的份量。
- 用户不仅关心热量，也关心价格、蛋白质、性价比、减脂友好度和具体在哪个窗口可以买到。
- “北大食堂健康记录”“清华食堂高蛋白榜”这类内容比泛泛推广 App 更容易被理解和转发。

本需求希望先以北大食堂为样板，后续扩展到清华和其它高校。

## 3. 产品目标

### 3.1 用户目标

用户可以：

- 在 App 里找到自己学校食堂的菜品。
- 看到菜品图片、价格、食堂位置、热量和蛋白质等信息。
- 在手动记录时快速选择校园食堂菜品。
- 上传自己拍到的食堂菜品，补充到公共食物库。
- 在圈子里浏览高质量校园食堂内容。

### 3.2 平台目标

平台可以：

- 把校园食堂数据沉淀为公共食物库中的高价值内容。
- 通过首页、手动记录、公共食物库、圈子、赚积分多入口放大校园食堂场景。
- 通过用户贡献逐步补全学校、食堂、窗口、价格和菜品数据。
- 先验证“校园场景是否能带来使用和传播”，再考虑邀请码、校园大使和收益分成。

## 4. 非目标

MVP 暂不做：

- 现金提现。
- 自动佣金分成。
- 多级分销。
- 完整校园大使后台。
- 食堂官方实时菜单。
- 食堂库存、排队、支付。
- 全国高校一次性全量覆盖。
- 复杂审核后台。

MVP 重点是把校园食堂作为公共食物库的一个高价值场景跑通。

## 5. 产品原则

1. **数据沉淀在公共食物库**
   校园食堂菜品不是一个完全独立的新食物体系，而是公共食物库中的一种特殊场景数据。

2. **前端展示要更显眼**
   虽然数据属于公共食物库，但校园食堂需要在首页、手动记录、公共食物库和圈子中被更突出地展示。

3. **价格是核心字段**
   价格不是备注。校园食堂场景下，价格和营养信息同等重要。

4. **先自动发布，后续再治理**
   MVP 阶段不做复杂审核，用户提交后可以自动发布。后续通过纠错、删除、下架和精选机制控制质量。

5. **圈子只展示高质量校园内容**
   圈子不适合展示普通食物库条目，只适合展示有传播价值的校园食堂内容，例如北大/清华食堂菜品、榜单、精选推荐。

## 6. 核心用户路径

### 6.1 浏览校园食堂菜品

1. 用户从首页点击“校园食堂”。
2. 进入校园食堂分区。
3. 用户选择学校，例如北京大学。
4. 用户选择食堂、楼层或窗口。
5. 用户浏览菜品列表。
6. 列表展示菜品图片、菜名、价格、热量、蛋白质、食堂位置。
7. 用户点击菜品进入详情。
8. 用户可以收藏、纠错或一键记录。

### 6.2 手动记录校园菜品

1. 用户进入手动记录。
2. 在食物来源或分类区域看到“校园食堂”入口。
3. 用户进入校园食堂来源频道。
4. 用户筛选学校/食堂，或直接搜索菜名。
5. 用户选择菜品。
6. 系统按该菜品默认份量和营养估算加入本餐记录。
7. 用户可调整份量、餐次和实际摄入比例。

### 6.3 上传校园食堂菜品

1. 用户从“赚积分”或校园食堂专区点击“补充菜品”。
2. 用户拍摄或上传食堂菜品图片。
3. 用户填写菜名、学校、食堂、楼层/窗口、价格。
4. 系统可复用现有食物识别能力估算营养。
5. 用户确认后提交。
6. 菜品进入公共食物库，并被标记为校园食堂内容。
7. 若符合奖励规则，给用户发放公共食物库上传奖励积分。

### 6.4 圈子浏览校园内容

1. 用户进入圈子。
2. 默认推荐流中可以混入少量精选校园食堂内容。
3. 用户也可以主动切换到“校园食堂”筛选。
4. 校园卡片展示学校、食堂、菜品、价格、热量和蛋白质。
5. 点击卡片进入菜品详情。

## 7. 入口设计

### 7.1 首页入口

首页增加一个“校园食堂”功能卡片。

要求：

- 入口应明显，但不要抢走首页记录食物的主流程。
- 点击后进入公共食物库中的校园食堂分区。
- 首版可以默认展示北大食堂内容。

示例文案：

- 标题：校园食堂
- 副标题：查食堂菜品热量、价格和蛋白质

### 7.2 公共食物库入口

现有公共食物库页面需要升级，不再只是简单列表。

建议顶部增加场景分区：

- 全部
- 校园食堂
- 我的收藏
- 我上传的

点击“校园食堂”后，展示学校/食堂筛选和校园菜品列表。

### 7.3 手动记录入口

手动记录页增加“校园食堂”来源频道。

要求：

- 用户可以在手动记录中直接选校园食堂菜品。
- 校园食堂数据不要只混在普通主食/肉蛋奶/菜肴分类里，否则用户很难发现。
- 搜索时也应能搜到校园食堂菜品。

### 7.4 赚积分入口

现有“公共食物库上传”任务可以扩展为支持校园食堂菜品。

建议文案：

- 任务名：上传公共食物/校园食堂菜品
- 说明：补充真实菜品、价格和位置，审核或规则通过后获得奖励积分。

MVP 可以不新增独立积分任务，先复用公共食物库上传奖励。

### 7.5 圈子入口

圈子默认推荐流可以混入少量高质量校园食堂卡片。

同时增加一个筛选项：

- 校园食堂

该筛选下只展示校园食堂相关内容。

## 8. 页面需求

### 8.1 校园食堂首页/分区页

页面目标：让用户快速找到学校食堂菜品，并进入记录或详情。

核心模块：

- 学校选择。
- 食堂筛选。
- 搜索框。
- 热门菜品。
- 高蛋白推荐。
- 低热量推荐。
- 性价比推荐。
- 补充菜品按钮。

菜品卡片展示：

- 菜品图片。
- 菜名。
- 学校/食堂/楼层/窗口。
- 价格。
- 热量。
- 蛋白质。
- 标签，例如高蛋白、低脂、减脂友好、价格待补充。
- 一键记录入口。

### 8.2 菜品详情页

页面目标：展示一个校园菜品的完整信息，并支持记录和纠错。

必须展示：

- 菜品图片。
- 菜品名称。
- 学校。
- 食堂。
- 楼层/窗口。
- 价格。
- 价格更新时间。
- 估算份量。
- 热量。
- 蛋白质、碳水、脂肪。
- 是否适合减脂。
- 贡献者信息。
- 收藏。
- 一键记录。
- 纠错入口。

可选展示：

- 每元蛋白质。
- 每 100 kcal 价格。
- 同食堂相似菜品。
- 圈子相关动态。

### 8.3 上传/补充菜品页

页面目标：让用户快速上传一个校园食堂菜品。

字段要求：

- 图片：必填。
- 菜名：必填。
- 学校：必填。
- 食堂：必填。
- 楼层：选填。
- 窗口：选填。
- 价格：建议填写，但允许未知。
- 价格类型：默认固定价。
- 份量描述：选填。
- 用户备注：选填。

提交后：

- 菜品自动发布。
- 菜品出现在公共食物库的校园食堂分区。
- 菜品可在手动记录中被搜索和选择。
- 若符合奖励规则，发放公共食物库上传奖励积分。

### 8.4 圈子校园卡片

圈子里的校园食堂卡片需要和普通饮食动态区分。

卡片展示：

- 菜品图片。
- 菜名。
- 学校/食堂。
- 价格。
- 热量。
- 蛋白质。
- 来源标识：校园食堂。

点击行为：

- 点击进入菜品详情页。

展示规则：

- 默认推荐流中只混入少量精选校园内容。
- 普通公共食物库条目不应进入圈子默认流。
- 校园内容应优先展示北大、清华等高质量数据。

## 9. 数据字段需求

本节描述产品字段，不限定具体数据库设计。

### 9.1 基础信息

- 菜品名称。
- 图片。
- 菜品描述。
- 贡献用户。
- 创建时间。
- 更新时间。
- 是否校园食堂内容。

### 9.2 校园位置信息

- 学校。
- 校区，选填。
- 食堂。
- 楼层，选填。
- 窗口，选填。
- 展示用位置文案。

示例：

```text
北京大学 · 学一食堂 · 一层 · 麻辣烫窗口
```

### 9.3 价格信息

价格是核心信息。

需要支持：

- 固定价，例如 `12元/份`。
- 称重价，例如 `28元/kg`。
- 区间价，例如 `8-15元`。
- 套餐价，例如 `18元/套餐`。
- 未知价，例如 `价格待补充`。

字段含义：

- 价格类型。
- 价格数值。
- 价格区间。
- 价格单位。
- 价格展示文案。
- 价格采集日期。

### 9.4 营养信息

至少展示：

- 估算份量。
- 热量。
- 蛋白质。
- 碳水。
- 脂肪。

可选展示：

- 减脂友好。
- 每元蛋白质。
- 每 100 kcal 价格。
- 推荐理由。

## 10. 菜品类型

### 10.1 固定单盘菜

适合 MVP 首版。

示例：

- 番茄炒蛋。
- 黄焖鸡饭。
- 鸡胸肉套餐。
- 牛肉饭。

要求：

- 可以按一份菜直接记录。
- 有固定或大致固定价格。
- 有图片和营养估算。

### 10.2 自选/称重类

示例：

- 麻辣烫。
- 自选称重菜。
- 冒菜。

MVP 不需要完整拆成食材库。

首版可以记录为窗口或常见组合：

- `麻辣烫窗口，28元/kg`
- `低脂高蛋白麻辣烫常见组合`
- `素菜饱腹组合`

后续再考虑食材组件化。

### 10.3 套餐/组合餐

MVP 可以先作为一个整体菜品记录。

后续再考虑拆分为主菜、主食、配菜和汤。

## 11. 质量与纠错

MVP 暂不做复杂审核。

需要提供这些兜底能力：

- 用户可以提交纠错。
- 用户可以补充价格。
- 上传者可以删除或下架自己上传的条目。
- 平台后续应能隐藏明显错误内容。
- 圈子推荐只展示精选校园内容，不展示所有上传内容。

常见错误包括：

- 菜名错误。
- 价格错误。
- 食堂/窗口位置错误。
- 图片质量差。
- 营养估算明显不合理。
- 重复菜品。

## 12. MVP 范围

### 12.1 必须做

- 首页增加校园食堂入口。
- 公共食物库增加校园食堂分区。
- 公共食物库上传支持校园食堂字段。
- 手动记录增加校园食堂来源频道。
- 校园菜品支持价格展示。
- 菜品详情展示学校、食堂、窗口、价格和营养信息。
- 圈子默认流可混入少量精选校园食堂内容。
- 圈子支持校园食堂筛选。
- 赚积分入口支持上传校园食堂菜品。

### 12.2 暂不做

- 独立校园大使后台。
- 现金提现。
- 自动佣金。
- 多级邀请。
- 食堂官方菜单同步。
- 复杂人工审核流。
- 麻辣烫完整食材组件库。
- 多学校复杂管理后台。

## 13. 首批样板建议

建议先做北大一个食堂样板。

首批数据目标：

- 1 个学校：北京大学。
- 1 个食堂。
- 30-50 个菜品。
- 80% 菜品有图片。
- 80% 菜品有价格。
- 80% 菜品有热量和蛋白质估算。

如果效果好，再扩展到：

- 北大更多食堂。
- 清华食堂。
- 其它学校。

## 14. 验收标准

### 14.1 浏览验收

- 用户能从首页进入校园食堂分区。
- 用户能按学校和食堂浏览菜品。
- 菜品卡片能看到图片、价格、热量、蛋白质和位置。
- 用户能进入菜品详情页。

### 14.2 记录验收

- 用户能从手动记录进入校园食堂来源频道。
- 用户能搜索校园食堂菜品。
- 用户能把校园食堂菜品加入一餐记录。
- 记录后的热量和营养能进入首页统计。

### 14.3 上传验收

- 用户能从赚积分或校园专区进入上传页。
- 用户能填写学校、食堂、菜名和价格。
- 提交后菜品能出现在校园食堂分区。
- 符合规则时能获得公共食物库上传奖励积分。

### 14.4 圈子验收

- 圈子默认推荐流中可以出现少量精选校园食堂卡片。
- 校园卡片展示价格、位置和营养信息。
- 用户可以切换到校园食堂筛选。
- 点击校园卡片能进入菜品详情页。

## 15. 指标

建议观察：

- 校园食堂入口点击人数。
- 校园食堂菜品浏览量。
- 菜品详情点击率。
- 一键记录转化率。
- 校园菜品上传数。
- 有价格菜品占比。
- 手动记录中校园菜品使用次数。
- 圈子校园卡片点击率。
- 上传用户次日留存。

## 16. 给工程师的交付要求

工程师阅读本 PRD 后，需要输出：

1. 技术方案。
2. 数据结构设计。
3. 前后端改动范围。
4. 接口设计。
5. 工期评估。
6. 风险点。
7. 需要产品确认的问题。

产品侧只要求校园食堂数据属于公共食物库的高价值场景，不要求工程师照搬某一种具体技术实现。

## 17. 当前结论

首版方向：

- 不做独立校园食堂大系统。
- 不做提现和分成。
- 不做复杂审核。
- 先把校园食堂作为公共食物库的一个高价值场景。
- 在首页、公共食物库、手动记录、赚积分和圈子中形成完整闭环。
- 价格、位置和营养信息是校园食堂菜品的核心展示信息。
