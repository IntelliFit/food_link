# 餐次默认、混合录入与整餐纠错修复

日期：2026-10-14。此文补充 `manual-food-feedback-fixes-2026-10-14.md`；前一轮 18g 自定义份量、商品编辑删除、核对提交等修复继续保留。

## 问题及处理

### 午餐默认成晚餐，早加餐默认成午加餐

推荐餐次之前优先作息规则，再按当天记录顺延。顺延函数漏了“当前餐次已经存在”的检查，只要最新记录超过一小时就往下一正餐跳。例如 12:30 只有 10:43 的早餐记录，也可能默认晚餐。作息规则又缺早加餐/晚加餐；手动页还会读取其它识别会话的全局旧餐次。推荐请求晚返回也可能盖掉用户手选。

现在默认建议按录入时间分六餐次，前后端规则一致；客户端发送 `ref_time`，后端按北京时间解释。当天已有记录不推动下一餐，手动新餐不继承全局旧餐次，手选之后的异步响应不再覆盖选择。结果页沿用当前识别会话的明确餐次，保存以确认餐次为准，历史记录不批量改写。

时段保持原六时段：00:00–05:00 晚加餐，05:00–10:30 早餐，10:30–11:30 早加餐，11:30–14:30 午餐，14:30–17:00 午加餐，17:00–21:00 晚餐，21:00–24:00 晚加餐。自定义作息仍保存在健康档案，但不再把时段中的早加餐变为另一正餐。

### 拍照结果无法直接用食物库补入正确项

以前结果页“添加食物”只建空白行，食物库则保存独立记录。现在结果页食物明细和纠错抽屉都有“从食物库添加”，复用原食物库的常见/自定义/校园等目录、份量和营养数据。

选择页进入 `picker=1` 模式，选完核对后“确认添加到本餐”，通过当前页面的 EventChannel 返回原清单；该动作不调用整餐保存接口。取消/直接返回不提交餐食，不改变原餐次或全局记录日期。食物库来源 ID、自定义来源、图片和实际重量随项保留；营养按所选实际份量算。最终仍在结果页确认一次餐次、保存一餐。

### 更正一个食品时，其它未修改食品的热量也变化

旧纠错把完整清单重新交给模型和营养库。旧后处理只补无法解析的项，没有保留已确认项的原快照；因此未改名称或重量也可能被重新估算。已有“单项重算”没有覆盖此旧入口。

现在普通结构化纠错按原食物标识合并：

- 未修改项直接保留原项，不重新估算营养。
- 只改重量按原营养密度换算。
- 改名或填写新增食品，仅分析目标项，按用户重量换算后合回原餐。
- 从食物库加入的项使用选择时的营养快照，不重新猜标签数据。
- 明确手填营养、重量/热量补充说明只应用到对应目标。
- 删除后不按数组位置匹配剩余食品；无 ID 的旧客户端仅用唯一原名称配对。重复原项标识报错。
- 实际摄入比例、来源、未修改项重量与营养保留，整餐合计和点评由最终清单更新。

补充说明支持原有重量/热量解析及常见明确改名“不是A，是B”“将A改为B”。名称和重量优先直接改列表；模糊说明不会默认触发整餐重新估算。复杂菜品应填写具体食物名称，失败保留原餐；没有把该入口改成后台无提示重跑整餐。

### 同一午餐/晚餐分次记录时，完整点评仍分开

前一轮当天页已有同餐次营养合计，本轮新增“整餐点评”页。点击当天页的餐次点评卡，按当前日期和餐次读取本人全部记录，显示搭配、PFC 供能比例、进食顺序、吸收与利用、情境建议、可用的饮食比例建议以及全部食品。照片与食物库分次录入也能一起查看。

原记录保留，在整餐页可打开各条记录修改，返回重新读取并汇总。不创建重复摄入，不删除/重写历史记录，不混入他人的公开记录或其它日期/餐次。不同来源的旧 AI 点评不会简单拼起来冒充新整餐分析。

混合清单或纠错后的合并点评是明确标示的营养数据点评，已有未修改识别餐食的 AI 点评保留。整餐营养点评不新增模型请求/积分费用；改名或新增未知食品仍走现有纠错任务及积分提示，不承诺免费。此次未新增数据库结构，无迁移命令。

## 另一台电脑/手机的真实交互验收

准备：更新 `dev` 或 `main` 最新代码；本地开发使用原项目原账号的 `npm run dev:weapp`，不要用生产包冒充本地 watch，不要切换模拟账号。体验版需确认公众平台选择本次说明对应的新包。体验 API 应为 `dev.api.healthymax.cn`，正式版为 `api.healthymax.cn`。

1. **默认餐次**：午餐时段、当天已有超过一小时前的早餐，分别打开拍照、文字和手动入口，默认仍午餐。10:30–11:30 默认早加餐。手选后等待推荐完成，不应跳回。上一晚餐未保存，再开手动新餐，不应继承晚餐。历史编辑不改原餐次。
2. **混合清单**：识别 A/B/C，删除 B，从食物库选 D，确认添加回到 A/C/D。再打开库取消，A/C/D 不变。查看份量、热量，最后保存只新增一餐，合计不含 B、不重复 D。
3. **18g 自定义**：从结果页库选择已录的咖啡18g一份，返回应18g、相应约8.1kcal；两份36g约16.2kcal。确认添加不能变成350g，不能提前保存整餐。自定义编辑/删除功能仍可用。
4. **按项更正**：记录 A/B/C 的名称、重量、营养、实际摄入比例；把 B 改为 D，在旧纠错抽屉提交。A/C 逐字段保持，D 按当前重量重算，合计准确。不只验证总热量或“任务完成”。直接单项编辑也重复确认。
5. **重量/删除/新增**：只改 B 克数，按原每克营养成比例更新；删除 B 后 A/C 对应不串位；从库补 D 营养应与库实际份量一致。失败/取消不覆盖原餐、不重复提交。
6. **摄入比例**：将 A 设50%、C设75%，纠错 B 后比例和实际摄入保持，合计按比例计算。比例为0的食品不算摄入，也不生成“吃它”的顺序建议。
7. **统一回看**：同一天午餐分别保存拍照与食物库记录，点当天页“查看整餐完整点评”，应同时包含两条的全部食物。晚餐/其它日期不混入。修改/删除一条后返回刷新，合计/点评同步，当天摄入不增加额外记录。
8. **来源标示**：更正/混合后的点评标示“营养点评”；未修改识别餐原 AI 点评仍可回看。整餐页原记录入口可修改本人的私有记录，不要求公开权限。
