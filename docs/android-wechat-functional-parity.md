# Android 与微信小程序功能一致性矩阵

更新时间：2026-07-23

## 验收口径

页面存在或能够打开不代表功能一致。一个功能只有同时满足以下条件，才可标记为“已实测一致”：

1. 入口、参数和默认值一致。
2. 调用相同业务接口，或调用语义等价的 Mobile API Client 方法。
3. 请求体、鉴权、分页、排序、过滤条件一致。
4. 成功后数据库结果、任务状态和积分/会员等副作用一致。
5. 本地缓存、跨页事件、刷新机制和返回路径一致。
6. 加载、空态、错误、重试、权限拒绝和重复提交行为一致。
7. 相机、相册、文件、分享、登录、支付、通知等平台能力有 Android 等价实现。
8. 通过自动化契约测试，并在 Android 模拟器完成至少一次真实交互验证。

状态定义：

- `已实测一致`：代码、接口副作用和 Android 运行时均已验证。
- `部分一致`：主要流程存在，但仍有已知功能或副作用差异。
- `待实现`：小程序已有功能，Android 尚无等价实现。
- `平台差异待决策`：无法直接复用微信小程序能力，需要 Android 产品/技术方案。

## 当前基线

- 小程序功能入口源码：67 个页面入口。
- Android 页面实现：63 个 Screen。
- 页面数量仅用于定位源码，不作为一致性结论。
- Android TypeScript 类型检查通过。
- Android Gradle `:app:assembleDebug` 构建通过。
- `cn.healthymax.foodlink` 已安装并运行于 `Pixel_7` AVD。
- 登录页渲染、Metro 加载、协议勾选交互已验证。

## 优先修复顺序

1. P0：图片分析 → 等待 → 结果 → 保存记录 → 首页即时刷新。
2. P0：登录/Token/账号安全与健康档案首次流程。
3. P0：手动记录、单日记录、记录详情与食谱闭环。
4. P1：保质期、身体指标、统计与积分券。
5. P1：社区、好友、私信、公共食物和校园。
6. P2：分享海报、邀请奖励、宠物、用户群等外围能力。
7. 单独决策：Android 支付与自动续费。

## 完成定义

只有当矩阵中除“平台差异待决策”外的项目全部变为“已实测一致”，并且自动化测试通过，才能对外宣称 Android 与微信小程序功能一致。
