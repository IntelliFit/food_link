## 讨论：Mobile App Release 自动发布技术路线
- 用户希望 push 后点一下、输入命令或全自动发布一个 release App 版本，并重点考虑中国大陆用户不能直接依赖 GitHub Release 下载。
- 推荐路线：GitHub 负责 CI 触发和构建记录，腾讯云 COS + 国内 CDN + 自有域名负责用户下载分发。
- 不建议只覆盖 `latest/` 文件夹作为唯一发布方式；建议保留不可变版本目录，并用 `channels/latest.json` / `channels/stable.json` 这类小 manifest 指向当前版本。
- 产物建议包括 APK/AAB 或安装包、sha256、manifest、变更说明、commit、构建号和发布时间；发布时先上传版本目录，再更新 channel manifest，便于回滚、灰度、审计和避免半发布。
- `latest/` 可以作为兼容入口保留，但不应替代版本化归档。
- 用户明确倾向不要普通 push 自动构建 App；后续实现应以手动命令、GitHub Actions 手动触发或明确 release tag 为主。
- 当前仓库已有 `build:mobile:android:apk` / `build:mobile:android:aab` 和 EAS 构建脚本，但未发现 `eas.json`；实现 release 自动化前需先补齐 EAS profile 或确认现有远端配置。
