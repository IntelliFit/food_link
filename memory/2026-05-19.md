## Packaged snack recognition path

- Implemented `type=daily_food|snack` for food analysis items. Unknown/missing type defaults to `daily_food` to preserve old behavior.
- Added `packaged_food_library` and `packaged_food_aliases` schema/domain/repo support. `snack` items first resolve against packaged DB; hits override model-estimated weight with `serving_weight_g` or `net_weight_g` and use `nutrition_source=packaged_food_library`.
- Precision item metadata now propagates `type`, so precision estimates can also use packaged DB during `ApplyDBFirstToItems()`.
- Added `scripts/enrich_packaged_foods.py` and `npm run nutrition:enrich-packaged` to collect public packaged snack data via web snippets + configured AI extraction, with dry-run support.
- Verified app compile smoke, worker prompt tests, script compile/help, package JSON parse, and diff-check. SQLite-backed repo/analyze tests were blocked by local `CGO_ENABLED=0`; DB migration was not run because target DB was not confirmed.
