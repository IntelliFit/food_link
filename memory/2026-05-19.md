## Packaged snack enrichment API URL fix

- User ran `npm run nutrition:enrich-packaged -- --dry-run --limit 20` from `backend/` and got `404 Client Error: Not Found for url: https://api.deepseek.com/`.
- Root cause: `scripts/enrich_packaged_foods.py` treated `llm_api_url` as the full chat completions endpoint. Some config values are base URLs like `https://api.deepseek.com`.
- Fixed by adding `normalize_chat_completions_url()`: preserves URLs ending in `/chat/completions`, appends `/chat/completions` to `/v1`, otherwise appends `/chat/completions` to the base URL.
- Verified `python -m py_compile scripts/enrich_packaged_foods.py` and script `--help`.

## Packaged snack enrichment skip existing support

- User asked whether packaged snack enrichment can skip existing data instead of starting over every run.
- Added local processed state support in `scripts/enrich_packaged_foods.py`, default `scripts/enrich_packaged_foods.state.json`, gitignored.
- Default behavior now skips queries recorded in state and, for non-dry-run DB writes, skips rows already present in `packaged_food_library` by `normalized_name`.
- Added `--no-skip-processed` to ignore local state and `--no-skip-existing` to reprocess DB-existing rows.
- Low-confidence skips and dry-run successes are also marked in state so repeated dry-run batches do not restart from the first seed unless the user opts out.
- Verified script py_compile, `--help`, and `git diff --check` for touched files.

## Packaged snack enrichment database name fix

- User hit `psycopg2.errors.UndefinedTable: relation public.packaged_food_library does not exist` while running from `backend/`.
