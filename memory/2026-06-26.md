## 运动分析：修复 exercise_items NOT NULL 冲突

### 问题
运动分析保存时上报：
```
ERROR: null value in column "exercise_items" of relation "user_exercise_logs" violates not-null constraint (SQLSTATE 23502)
```

### 根因
- `user_exercise_logs.exercise_items` 字段为 `jsonb NOT NULL DEFAULT '[]'::jsonb`。
- 短文本/图片等链路估算完成后，`exerciseItemsFromEstimate` 返回 `nil`（只有长文本 library MET 模式才生成 items）。
- `ExerciseRepo.CreateExerciseLog` 未对 nil 切片做归一化，GORM 序列化时插入 NULL，触发约束冲突。

### 修复
- `backend/internal/health/repo/exercise_repo.go`：在 `CreateExerciseLog` 中，若 `log.ExerciseItems == nil`，将其设为空数组 `[]map[string]any{}`，确保写入 `'[]'::jsonb`。
- `backend/internal/health/repo/exercise_repo_test.go`：新增 `TestExerciseRepo_CreateExerciseLog_NormalizesNilItems` 覆盖 nil 场景；并改用 `modernc.org/sqlite` 纯 Go 驱动，避免 CGO 限制。
- `backend/internal/health/service/exercise_service.go`：增强 `exerciseItemsFromEstimate`：
  - 长文本 library MET：保留现有 items。
  - 分段估算：把每个 segment 解析成独立 item，提取时长/组数/次数。
  - 单条 LLM（短文本/图片）：用 `exercise_type` 生成一个 item，并从描述中提取时长/组数/次数。
  - `EstimateCalories` 响应也返回 `exercise_items`。
- `backend/internal/health/service/exercise_service_test.go`：在短文本、分段、长文本、图片等测试中断言 `exercise_items` 非空且字段正确。

### 验证
- `go build ./internal/health/repo/... ./internal/health/service/... ./internal/health/domain/...` 通过。
- `backend/internal/health/repo/exercise_repo_test.go` 改用纯 Go SQLite 驱动（`modernc.org/sqlite`），解决本地 `CGO_ENABLED=0` 无法运行的问题。
- `go test ./internal/health/repo/... -run 'TestExerciseRepo' -count=1 -v` 全部通过（含新增的 nil items 归一化测试）。
- `go test ./internal/health/service/... -run 'TestExerciseService' -count=1 -v` 全部通过，短文本与长文本链路均正常：
  - 短文本：`TestExerciseService_EstimateCalories_ShortTextRun40MinutesUsesOriginalLLM`
  - 长文本：`TestExerciseService_EstimateCalories_LongTextUsesLibraryMET`、`TestExerciseService_EstimateCalories_LongTextCreatesPendingMET`

### 后续
- 无需数据库迁移，schema 已包含 NOT NULL DEFAULT。
- 修复部署后，运动分析的短文本、图片、分项估算等链路会生成结构化 `exercise_items`，前端可展示 `ExerciseActivityCards`；同时 nil 兜底保证数据库不触发 NOT NULL 冲突。

## Android App bottom camera button no-op fix

### Problem
- User clarified the issue was the installed Android App, not the WeChat mini program. After reinstalling the App, tapping the bottom camera/record button still did nothing.

### Root cause
- Real-device ADB on vivo V2366HA reproduced the no-op: tapping the bottom center button did not change the UI and produced no camera/permission logs.
- `CustomTabBar` wrote `showRecordMenuModal` and emitted `home-record-menu:request`, but `HomeScreen` no longer subscribed to `onHomeRecordMenuRequest` or rendered `RecordActionSheet`, so the event had no visible consumer.
- `CustomTabBar` also used `navigation.getParent()?.navigate('HomeTab')`; `HomeTab` is a tab route, not a parent RootStack route.

### Fix
- `apps/mobile/src/navigation/CustomTabBar.tsx`: changed the center button to call `navigation.navigate('HomeTab')`.
- `apps/mobile/src/screens/HomeScreen.tsx`: restored `onHomeRecordMenuRequest` subscription, focus-time `consumeHomeRecordMenuDate` fallback, and `<RecordActionSheet />` rendering.
- `apps/mobile/android/app/src/main/AndroidManifest.xml`: explicitly declared `android.permission.CAMERA`.

### Verification
- `npm --workspace apps/mobile run typecheck` passed.
- `git diff --check -- apps/mobile/src/navigation/CustomTabBar.tsx apps/mobile/src/screens/HomeScreen.tsx apps/mobile/android/app/src/main/AndroidManifest.xml` passed with existing LF/CRLF warnings only.
- `python scripts/release_mobile_android.py --build-local-apk --dry-run` built stable APK `dist/mobile-release/android/stable/0.0.1/4/foodlink-0.0.1-4.apk`.
- ADB installed that APK on vivo V2366HA and verified the bottom button opens the record action sheet with `拍照识别`, `相册上传`, `文本输入`, and `食物库输入`.

### Release
- User said the App is now fine and asked to release directly. Commit/push first so the Android release manifest points to the actual fix commit, then run `npm run release:mobile:android` from `main`.
