## 精准分项模式混合食物未拆分修复

- 用户实测「精准分项」模式时，明显混合食物 `鸡肉胡萝卜烩意面` 仍只返回 1 个 item，结果页显示 `包含成分（1种）`，无法分别调整鸡肉、胡萝卜、意面摄入比例。
- 判断：第一版 `strict_separate` 只新增入口和扣费/任务路由，后端 worker planner 仍按普通精准模式理解“主体食物”；对“一个菜名但多成分”的混合食物，模型会把整菜当成一个主体。
- 已修改 `backend/internal/worker/worker.go`：
  - precision plan 读取并识别 `execution_mode=strict_separate`，并透传给子估计和聚合任务。
  - planner prompt 在精准分项模式下明确要求牛肉面、烩意面、盖饭、炒饭、炒面、汤面、麻辣烫、沙拉、咖喱饭、便当等混合食物尽量拆成主食基底、蛋白质、可见蔬菜/配料、显著酱汁/汤底。
  - 新增 `forceSeparateMixedDishPlan` 兜底：当 planner 仍只返回一个整菜名，且菜名中能稳定拆出成分类别时，自动拆成成分项；`鸡肉胡萝卜烩意面` 会拆为 `意大利面`、`鸡肉`、`胡萝卜`。
  - 分项估计 prompt 增加“只估计该成分，不把其它配料并入”的规则。
- 新增 worker 回归测试覆盖该兜底和 prompt 规则。
- 验证通过：`go test ./internal/worker -run "TestForceSeparateMixedDishPlan|TestPrecisionPrompts_(ForceEdibleNetWeight|ForceFoodTypeCandidates|StrictSeparateMixedDishRules)" -count=1`，`go test ./internal/worker -count=1`，以及相关 `git diff --check`（仅 LF/CRLF warning）。
- 本轮没有改小程序页面/组件/样式/路由或交互，未做 weapp-devtools 截图验证；需后端 worker 重启/部署后用用户同图复测。
