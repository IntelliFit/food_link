## 公共食物库地址搜索失败根因修复
- 用户明确不需要公共食物库“搜索地址”页加系统地图选点兜底，要求查明为什么最早可用、现在失败，并尽量修根因。
- 已撤回此前新增的 `Taro.chooseLocation` 兜底、`chooseLocation` 私有接口声明和页面“系统地图选点”入口；前端 location-search 当前无内容 diff。
- 根因拆分：
  - 当前配置的天地图 key 直连 `/v2/search` 和 `/geocoder` 均返回 `403 Forbidden`，假 key 返回 `400 Bad Request`；高概率是当前 key 被识别但权限/白名单/配额/服务状态不可用。
  - Go 后端迁移时丢掉了前端已发送的 `count/lon/lat/radius_km`，导致搜索不再按当前地图附近范围查询；这不解释 403，但会导致搜索体验退化。
- 已修后端迁移漂移：
  - `UtilityHandler.LocationSearch` 重新接收 `count/lon/lat/radius_km` 并传给 service。
  - `LocationService.SearchAddress` 按坐标和半径计算天地图 `mapBound`；无坐标时使用中国范围默认边界，`count` 默认 10、最大 20。
- 验证：
  - `go test ./internal/utility/service -run "TestLocationService_" -count=1` passed。
  - `go test ./internal/utility/handler -run "TestLocation" -count=1` passed。
  - `go test ./internal/app -run '^$'` passed。
  - scoped `git diff --check` passed（仅 LF/CRLF warning）。
- 后续：线上要真正恢复，需在生产配置/Apollo 中替换或恢复可用 `TIANDITU_TK` 并部署后端；若仍 403，查天地图服务权限、Referer/IP 白名单、配额和账号状态。
