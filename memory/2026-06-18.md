## 意见反馈飞书通知失败排查

- 用户反馈提交意见反馈后没有飞书通知，线上日志为 `意见反馈飞书通知失败`，错误 `feishu api error code=19001 msg=param invalid: incoming webhook access token invalid`。
- 只读拉取 Apollo `main/app-config.yaml` 验证飞书配置：`feishu.feedback_webhook_url` 与 `feishu.report_webhook_url` 均存在，二者 token 不同；Apollo `local` 和 `main` 当前两组飞书 token 相同。
- 用 Apollo `main` 配置实际 POST 测试：反馈 webhook 返回 `code=19001 incoming webhook access token invalid`；举报 webhook 返回 `code=0 success`。
- 结论：反馈通知失败根因是 Apollo 中反馈专用飞书机器人 webhook access token 已失效/不属于当前可用机器人，不是后端签名算法、反馈入库、异步通知链路或 Apollo 加载问题。
- 后续处理：在 Apollo 更新 `feishu.feedback_webhook_url` 和 `feishu.feedback_webhook_secret` 为有效机器人；如果反馈和举报可发同一群，可临时复用已验证成功的举报 webhook 配置。更新后重启/滚动后端服务加载新配置。
- 进一步对照用户提供的飞书机器人截图确认：Apollo/粘贴配置里的反馈 webhook 最后一段被写成 `aald61e8ed89`，截图实际是 `aa1d61e80d89`；反馈 secret 中 `w2O8` 的 `O` 被写成了数字 `0`。用截图 URL 加错误 secret 返回 `19021 sign match fail`，改成截图 secret 后返回 `code=0 success`。
- 最终根因确认：同事新增 report 飞书配置时曾用 OCR 录入/改动 feedback 配置，导致原本正确的 feedback webhook URL 和 secret 被相似字符污染。以后更新 webhook/secret 必须直接复制，不要 OCR 或手敲。
