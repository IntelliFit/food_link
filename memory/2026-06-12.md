# 2026-06-12 食物识别用户不信任行为打点

## 背景

`analysis_feedback_samples` 原本只收集用户点击「不对，纠正一下」的 correction 数据，共 86 条。为了构建算法不信任度评估模型，需要扩展采集用户在保存前对结果进行微调的行为（改重量、改营养素、只改比例但不改实质内容），以及「怀疑但懒得改」的隐性不信任行为（在结果页停留超过 15 秒但没有任何操作就保存）。

## 决策

1. **后端统一入口**：不新增多个 endpoint，统一用 `POST /api/analyze/feedback`，字段 `feedback_type` 区分行为类型。
2. **分辨率状态**：
   - correction（用户点击纠正）→ `user_corrected` 或 `still_distrust`（取决于是否成功生成新任务）
   - weight_mismatch / nutrition_mismatch / record_corrected → 均为 `still_distrust`（用户手动改了，但说明 AI 最初给的不准）
   - suspect_distrust → `still_distrust`（用户看了很久没动，说明有疑虑）
3. **去重策略**：
   - 旧 correction：按 `correction_task_id` ON CONFLICT UPDATE（保持原行为不变）
   - 新类型：按 `(feedback_type, source_task_id, source_record_id)` 查询后更新 `created_at`（软去重），避免同一用户在短时间内重复写入同一条不信任记录
4. **前端去重**：内存级 `Set<string>`，key 为 `sourceTaskId:sourceRecordId:feedbackType`，页面卸载时丢弃（不持久化）
5. **MealRecordEditModal 的 record_corrected 只算「实质修改」**：排除仅比例、份数、餐次变化的场景，避免误报

## 2026-06-12 追加：修复 `/api/analyze/feedback` 500 错误

### 现象

前端调用 `POST /api/analyze/feedback` 返回 500，`internal server error`。

### 根因

`TaskRepo.UpsertFeedbackSample` 对新类型做软去重时使用了：

```sql
COALESCE(source_task_id, '') = COALESCE(?, '')
```

但 PostgreSQL 中 `source_task_id` 是 `uuid` 类型，`''` 是 `text`，`COALESCE` 要求参数类型一致，导致 SQL 执行报错 500。

### 修复

1. 软去重查询改为分支条件：
   - 空值：`source_task_id IS NULL`
   - 非空：`source_task_id = ?`
2. 命中后更新从 `Updates(map[string]any{...})` 改为 `Select(...).Updates(&struct{...})`，避免 SQLite/PostgreSQL 对 JSON 字段序列化行为不一致，同时让 GORM 正确识别 nil 指针为 NULL。
3. 新增两个 repo 单元测试覆盖软去重和双 nil source ID 场景。
4. 前端 `submitFeedbackDeduped` 增加保护：当 `source_task_id` 与 `source_record_id` 都为空时直接返回，不发送无效请求。

### 验证

## 2026-06-12 追加：临时禁用前端 feedback 网络请求

应业务方要求，暂时关闭所有向 `/api/analyze/feedback` 发送的埋点网络请求，避免在排障/灰度期间继续写入 `analysis_feedback_samples`。

### 实现

- `src/utils/api.ts` 中 `submitAnalysisFeedback` 增加开关 `ANALYSIS_FEEDBACK_SUBMISSION_ENABLED`，当前设为 `false`。
- 开关关闭时函数直接返回 `{ message: 'feedback submission disabled' }`，不调用 `authenticatedRequest`。
- result / result-text / MealRecordEditModal 的开发者模式 UI 识别该状态，显示「feedback 已禁用」橙色标记，而不是绿色「已发送」。

### 恢复方法

把 `src/utils/api.ts` 中的 `ANALYSIS_FEEDBACK_SUBMISSION_ENABLED` 改回 `true` 即可恢复入库。
