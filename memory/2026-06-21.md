## 小程序健康档案保存 500 修复
- 问题：线上 `foodlink-main` 的 `PUT /api/user/health-profile` 返回 500，日志报 `unable to encode map[string]interface {} ... into text format for unknown type (OID 0): cannot find encode plan`。
- 只读确认：`ubuntu@154.8.205.78` 上 `foodlink-main` 3 个 Pod 均 Running 且 0 重启；同一路径 `GET /api/user/health-profile` 返回 200，失败集中在 PUT 保存写库。
- 根因：`backend/internal/user/service/user_service.go` 构造 `updates["health_condition"] = healthCondition`，最终经 `UserRepo.UpdateFields` 的 `Updates(map[string]any)` 写 PostgreSQL `jsonb` 字段；裸 Go map 未包装时 pgx 无法推断 jsonb 编码。
- 修复：`backend/internal/auth/repo/user_repo.go` 新增 `normalizeUserJSONUpdates`，在 `UpdateFields` 中统一将 `health_condition` 裸 map 包装成 `datatypes.JSONMap`；这样健康档案、健康关注、报告任务状态和兼容旧库登录路径都受保护。
- 新增测试：`backend/internal/auth/repo/user_repo_json_updates_test.go` 覆盖裸 map 包装和已包装 JSONMap 兼容。
- 验证：`go test ./internal/auth/repo -run 'TestNormalizeUserJSONUpdates' -count=1`、`go test ./internal/auth/repo ./internal/user/service -run '^$' -count=1`、`go test ./pkg/config -count=1`、`go build ./cmd/server` 通过。
- 限制：完整执行型 `go test ./internal/auth/repo ./internal/user/service -count=1` 在当前 Windows `CGO_ENABLED=0` 环境被既有 SQLite stub 问题阻塞；本轮未重启本地服务、未跑迁移、未部署线上。

## 2026-06-21 - Grafana Feishu HTTP 5xx alert implemented
- Status: completed in the live `observability` namespace and Grafana UI.
- Why an adapter was needed: Grafana 11 webhook contact points can send webhook payloads/headers, but the Feishu custom bot with signing requires Feishu-specific body fields (`timestamp`, `sign`, `msg_type`, `card`). A tiny in-cluster webhook adapter avoids any polling loop and keeps alerting event-driven.
- Kubernetes resources created: Secret/ConfigMap/Deployment/Service named `grafana-feishu-webhook` in namespace `observability`; sensitive Feishu webhook/sign secret/adapter bearer token are stored only in the Kubernetes Secret, not in repo notes.
- Contact point created in Grafana: `feishu-foodlink-alerts` of type `webhook`, pointing to `http://grafana-feishu-webhook.observability.svc.cluster.local:8080/webhook` with bearer auth.
- Alert rule created in Grafana: `Food Link main HTTP 5xx detected`, folder `Food Link`, evaluation group `foodlink-1m`, interval `1m`, pending period `0s`, receiver `feishu-foodlink-alerts`.
- PromQL saved: `sum(increase(food_link_http_requests_total{service_name="food_link-backend-main",status=~"5.."}[1m])) or vector(0)`; the `or vector(0)` fallback is required so a quiet minute returns 0 instead of Grafana No Data.
- Verification: adapter Deployment is 1/1 available, Pod Running with 0 restarts; a signed adapter POST returned Feishu success; Grafana Preview returned value `0` and Normal; Grafana list shows 1 normal rule under `Food Link / foodlink-1m`; copied Grafana SQLite confirmed the saved rule, PromQL, annotations, and receiver.
- Limit: no real production 5xx was intentionally generated, so the alert firing path was not tested by causing a live 500; only the adapter notification path and Grafana rule evaluation/save were verified.
