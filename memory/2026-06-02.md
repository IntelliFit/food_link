## 混合食物按成分摄入比例记录的产品讨论

- 用户提出牛肉面这类混合食物难题：同一碗里至少有牛肉和面，用户可能吃了 100% 牛肉但只吃 30% 面；当前如果把整碗当一个食物项，单一摄入比例无法表达这种情况。
- 初步判断：当前记录数据已有 item 级 `ratio/intake/weight`，所以只要识别结果能拆成多个 item，就能表达“牛肉 100%、面 30%”；真正缺口在识别与交互是否把混合食物拆成成分项。
- 产品方向倾向：普通模式保持轻量，混合菜无法可靠拆分时仍可按一道常见菜记录；精准模式更适合作为“混合食物拆分/按成分调整摄入比例”的入口，尤其适合牛肉面、盖饭、麻辣烫、沙拉、汤面等场景。
- 后续若实现，应让精准模式在可见或用户描述明确时拆出成分项，例如“牛肉面-牛肉 / 牛肉面-面条 / 汤底”，并在结果页允许逐项调整比例；无需立刻改代码。
- 用户随后要求加一个可试玩的新模式，名字倾向“精准模式-分开食物估计”或更简洁。已实现为「精准分项」，内部 `execution_mode=strict_separate`。
- 「精准分项」出现在拍照分析页模式选择中，按精准模式会员门槛和 4 积分计费；底层复用现有 precision 分项 planner / 子项估计 / 聚合链路，loading、历史、结果页都显示「精准分项」。
- 为减少试玩阻力，暂不把该模式写入用户默认模式或数据库 check constraint；`precision_sessions.execution_mode` 继续写兼容旧约束的 `experimental`，任务 payload 中保留 `strict_separate`。
