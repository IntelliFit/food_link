## 意见反馈与 feedback-bot 同步调研
- Current Food Link flow: weapp/App feedback submits to `/api/feedback`, image upload uses `/api/feedback/upload-image`, and backend persists records in `user_feedback`.
- Submission side effects: backend sends a submit-confirmation system message and optionally sends a Feishu custom-bot card via `feishu.feedback_webhook_url`; this is notification-only, not feedback-bot/Bitable lifecycle sync.
- Admin flow: `/api/admin/feedback/:feedback_id/status` updates `user_feedback.status`, `resolution_message`, optional reward credits/ledger, and sends an in-app result message. It does not update feedback-bot or Feishu Bitable today.
- feedback-bot already has the better cross-project Feishu/Bitable normalization path: `/api/messages/ingest` with `project_key`, project-scoped dedupe/batching, LLM classification, project-specific Feishu webhook routing, and optional Bitable record creation.
- Recommended implementation direction: make `food_link` source of truth for user feedback/admin adoption state, and add an internal integration to feedback-bot for Feishu/Bitable create/update sync rather than duplicating direct Feishu/Bitable logic in the Go backend.
