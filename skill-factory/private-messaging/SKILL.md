# 私信功能基础 PD 总结

## 功能定位

私信是用户之间的一对一点对点沟通能力，当前 Mobile App 入口在「圈子」相关页面。它承担好友、关注用户之间的轻量沟通，也承接系统消息会话。

## 基础信息架构

- 会话列表展示最近会话、对方头像/昵称、最后一条消息预览、最后消息时间和未读数。
- 系统消息使用固定用户 ID `00000000-0000-0000-0000-000000000000`，在列表和聊天页中以「系统消息」展示。
- 聊天页按时间正序展示消息，支持向上加载更早消息。
- 进入聊天页后刷新最新消息，并按固定间隔轮询。
- 普通聊天显示文字输入、发送按钮和图片发送入口；系统消息会话隐藏输入区。

## 消息类型

- `text`：展示文本内容，支持复制文本。
- `image`：展示图片，长按复制图片 URL。
- `system`：平台通知或处理结果，仅展示，不参与普通消息操作。

## 长按操作

- 用户长按普通文字或图片消息时，底部弹出操作菜单。
- 所有普通消息都有「复制」。
- 自己发送的普通消息显示「删除」。
- 对方发送给自己的普通消息显示「举报」。
- 菜单底部固定「取消」。
- 删除采用撤回式软删除：删除后双方会话中都不再显示该消息，也不再参与会话预览、未读统计和已读处理。
- 举报会提交后端记录，默认原因是 `other`，补充说明标记为「来自私信长按举报」。

## 权限与边界

- 不能给自己发私信。
- 文字消息不能为空；图片消息必须有图片 URL。
- 只有消息发送者可以删除自己的普通消息。
- 只有消息接收者可以举报对方发来的普通消息。
- 不能删除或举报系统消息。
- 重复举报同一条消息应返回已有举报记录，避免重复创建。

## 数据与接口

- 会话消息表 `private_messages` 需要包含发送者、接收者、内容、图片、类型、已读状态、创建时间和软删除字段。
- 私信举报表记录举报人、被举报用户、消息 ID、原因、补充说明、消息快照、状态和创建时间。
- 基础接口：
  - `GET /api/messages/conversations`
  - `GET /api/messages/conversation/:user_id`
  - `POST /api/messages/send`
  - `PUT /api/messages/read/:user_id`
  - `GET /api/messages/unread-count`
  - `DELETE /api/messages/message/:message_id`
  - `POST /api/messages/message/:message_id/report`

## 验证要点

- 会话列表分页、未读数、最后消息预览正确。
- 聊天页轮询不会重复插入消息，历史分页顺序稳定。
- 发送文字后本地合并并静默刷新。
- 发送图片后图片可正常展示。
- 长按自己的文字/图片：菜单显示复制、删除、取消。
- 长按对方文字/图片：菜单显示复制、举报、取消。
- 删除后刷新页面消息不恢复，会话预览不再使用已删除消息。
- 举报成功后有明确反馈，重复举报不报错。
